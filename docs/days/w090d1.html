The last build sprint finishes Waymark’s features. Its first story, S11, is about what walkers see: an elevation profile for a route (height against distance, so a walker can see where the climbs are before setting off) and statistics for their walk log (distance by month, a rolling weekly total, how their pace compares with the rule). It brings Week 83’s pandas and matplotlib into the capstone, with the same rules: honest charts, labelled axes, data prepared in tested functions before anything is drawn, and checks that inspect the figure rather than its pixels.

  • Load a walk log into pandas and summarise it by month and by rolling week
  • Compare actual and estimated times, and chart the comparison
  • Keep data preparation in tested functions separate from drawing
  • Build a small dashboard figure with several charts

waymark_domain.py
import heapq


class UnknownPlace(LookupError):
    pass


class NoRoute(Exception):
    pass


def naismith_minutes(km, climb_m):
    return round(km / 5 * 60 + climb_m / 600 * 60)


class Route:
    def __init__(self, stops, km, climb_m):
        self.stops, self.km, self.climb_m = list(stops), km, climb_m

    @property
    def minutes(self):
        return naismith_minutes(self.km, self.climb_m)

    def __repr__(self):
        return f"Route({self.stops}, {self.km} km, {self.climb_m} m)"


class PathNetwork:
    def __init__(self, heights):
        self.heights = dict(heights)
        self.paths = {name: {} for name in self.heights}

    def _check(self, *names):
        for name in names:
            if name not in self.heights:
                raise UnknownPlace(name)

    def add_path(self, a, b, km):
        self._check(a, b)
        if km <= 0:
            raise ValueError("km must be positive")
        self.paths[a][b] = km
        self.paths[b][a] = km

    def climb(self, stops):
        return sum(max(0, self.heights[b] - self.heights[a]) for a, b in zip(stops, stops[1:]))

    def shortest(self, start, end):
        self._check(start, end)
        dist, prev, done = {start: 0}, {}, set()
        heap = [(0, start)]
        while heap:
            d, node = heapq.heappop(heap)
            if node in done:
                continue
            done.add(node)
            if node == end:
                break
            for nxt, km in sorted(self.paths[node].items()):
                if d + km < dist.get(nxt, float("inf")):
                    dist[nxt] = d + km
                    prev[nxt] = node
                    heapq.heappush(heap, (d + km, nxt))
        if end not in done:
            raise NoRoute(f"no route from {start} to {end}")
        stops = [end]
        while stops[-1] != start:
            stops.append(prev[stops[-1]])
        stops.reverse()
        return Route(stops, round(dist[end], 2), self.climb(stops))

from waymark_domain import PathNetwork

HEIGHTS = {"Mill": 40, "Weir": 55, "Church": 80, "Ridge": 310, "Farm": 120, "Wood": 150, "Lake": 60, "Island": 5}

         ("Weir", "Farm", 2.5), ("Farm", "Ridge", 2.0), ("Farm", "Wood", 1.5), ("Wood", "Lake", 2.0), ("Lake", "Mill", 3.5)]


def sample_network():
    network = PathNetwork(HEIGHTS)
    for a, b, km in PATHS:
        network.add_path(a, b, km)
    return network

Warm-up

Two lists, distance along the route and height at each stop, are an elevation profile. Drawn as a line, the steep last section to Ridge is obvious at a glance in a way that “270 m of climbing” isn’t.

An elevation profile

The profile’s x values are the cumulative distance at each stop (itertools.accumulate with an initial 0), and the y values the heights. Draw it as a line with a lightly filled area underneath, label both axes with units, and mark the stops. Two honesty rules from Week 83 apply with a twist: a profile’s y axis normally doesn’t start at zero (that would flatten every hill), but it must be labelled so nobody mistakes a 40 m rise for a mountain; and two profiles shown side by side must share the same scales, or the flatter route can look steeper.

The log as a DataFrame

The walk log (Week 88) becomes a DataFrame with one row per walk. Parse the day column into dates (pd.to_datetime), then:

  • by month: resample("MS") on the dates gives one row per month, including months with no walks (as zeros), which groupby on a month string wouldn’t;
  • rolling: a 28-day rolling sum of distance (rolling("28D", on="day")) shows whether the walker is doing more or less lately;
  • derived columns with assign: the Naismith estimate for each walk, and the ratio of actual to estimated time.

Return plain Python values (tolist, to_dict) from these functions, so the tests don’t depend on pandas’ printed formats, which differ between versions.

Pace against the rule

A scatter plot of estimated against actual minutes, with the line actual = estimate drawn across it, shows a walker’s pace at a glance: points above the line are walks slower than the rule. Day 2 of Week 88 summarised this as one number (the median ratio); the chart shows whether it’s consistent or whether hilly walks are where the time goes.

Prepare, then draw

Every chart in Waymark has two functions: one that prepares the data (pure, returns lists or a small DataFrame, easy to test exactly) and one that draws it (takes the prepared data, returns the figure, tested by inspecting the figure’s lines, bars and labels). Mixing them makes both harder to test and to change. The dashboard in the challenge is then just a layout calling the drawing functions.

Key idea

An elevation profile plots cumulative distance against height; label the axes with units, don’t force the y axis to zero, and share scales when comparing. Load the log into pandas, parse dates, use resample("MS") for months (with gaps as zeros), rolling("28D", on=...) for recent totals and assign for derived columns; return plain Python from tested functions. Compare actual and estimated times with a scatter and the actual = estimate line. Separate preparing data from drawing it; test the first exactly and the second by inspecting the figure.

Bug hunt10 points
A hill flattened

Starting the profile’s y axis at zero squashes a 270 m climb into a gentle slope (and wastes most of the chart): it prints y from 0.0. Start it just below the lowest height, so it prints y from 20.0.

Bug hunt10 points
February disappeared

Grouping by a month string only gives months that have walks, so the chart’s February gap vanishes: it prints ['2026-01', '2026-03']. Resample by month start so February appears with 0, and it prints ['2026-01', '2026-02', '2026-03'].
