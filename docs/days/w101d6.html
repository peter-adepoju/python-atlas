Mixed review

Exercise10 points
Reading time

Write reading_time(markdown, wpm=200): the minutes (rounded up, at least 1) to read the text of a Markdown page at wpm words a minute, leaving out fenced code blocks and the # marks of headings.

Exercise10 points
Counting the open questions

Write question_summary(transcript, speaker="Mentor"): from lines "SPEAKER: TEXT", take the speaker’s lines that end with ? and return a dict with open (starting with what, how, why, which or where), leading (containing don’t you think, isn’t it or shouldn’t you) and closed (the rest), ignoring case.

How this course is made

Every day of this course is a Markdown file with blocks like the ones you’ve used all along: predictions, exercises with checks, quizzes. A quiz block is a list of questions, each with q, options, the index of the right answer, and an explain. Writing good ones is exactly Day 2’s work: run the code for the right answer, take wrong options from real misconceptions, and explain the gap in a sentence. Generating the block from data means the right answer can’t be wrong, which, as Day 1 showed, is easy to get wrong by hand.

Exercise50 points
Writing quiz blocks

Write quiz_block(quiz_id, items). Each item is a dict with q and explain, and either code and wrong (a list of wrong outputs) or options and answer. For a code item, run the code (capturing what it prints, stripped) to get the right answer; its options are the right answer plus the distinct wrong outputs that differ from it, sorted; and add a line code: | followed by the code indented by four spaces. Raise ValueError with "question N is too long" (over 120 characters), "question N needs 2 to 5 options", or "question N needs an explanation" (N counting from 1). Return the block: :::quiz id=QUIZ_ID, then per item - q: Q, options: [...] (as json.dumps of the list), answer: N, explain: E (with q and explain written with json.dumps), the code lines if any, and finally :::, all joined by newlines.

Teaching as the last test

This course has asked you to predict the output of thousands of lines of code. This week you wrote the predictions for someone else. Which was harder: getting the right answer, or choosing wrong options that would catch a real misunderstanding? The second is the better measure of how well you understand an idea.

Bonus: checking a review message

Exercise30 points
Bonus: is the review encouraging?

Write review_message_problems(message): report, in order: "start with thanks" unless the first line contains thank; "name what works" unless a line starts with What works well; "too many suggestions" if more than 3 lines start with - line; "end with a question" unless the last non-blank line ends with ? or contains ? followed by an offer; and "sounds harsh: WORD" for each of wrong, bad, terrible, obviously, just found as a whole word (ignoring case).
