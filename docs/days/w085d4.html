Part B: five problems

Exercise10 points
P1: Tests for discount codes

discounts.py has price_after(price, code): "TEN" takes 10% off; "HALF" takes 50% off orders of at least £20 (smaller orders pay full price); "FIVER" takes £5 off but never below £0; any other code raises ValueError. Results are rounded to 2 places. Write tests that pass on this code and catch all five broken versions.

discounts.py
def price_after(price, code):
    if code == "TEN":
        result = price * 0.9
    elif code == "HALF":
        result = price * 0.5 if price >= 20 else price
    elif code == "FIVER":
        result = max(0, price - 5)
    else:
        raise ValueError(f"unknown code {code}")
    return round(result, 2)
Exercise15 points
P2: Changing a URL’s query

Write with_params(url, **changes): the URL with its query string updated: each change sets that parameter (a list sets it several times), None removes it, other parameters keep their values, and the result’s parameters are sorted by name and encoded with urlencode(..., doseq=True). Keep the scheme, host, path and fragment. Then get_param(url, name, default=None): the parameter’s first value, or default.

Exercise15 points
P3: Library loans

With the given make_db(), write borrow(conn, book_id, borrower, today): in one transaction, refuse with ValueError("on loan") if the book has a loan with no returned date, else insert a loan due 14 days later (dates are YYYY-MM-DD text; use datetime.date). give_back(conn, book_id, today) sets returned on the open loan (ValueError("not on loan") if there isn’t one). overdue(conn, today): (title, borrower, days_late) for open loans past their due date, most overdue first (ties by title). Use ? parameters throughout.

Exercise15 points
P4: Weather summary

weather.csv (shown above) has daily temp and rain for two cities, with gaps. Write monthly(df): a list of (city, month, mean_temp, total_rain) sorted by city then month ("2026-01"), with the mean of the temperatures that are present and the sum of the rain that is present, both rounded to 2 places. filled(df): a new DataFrame where each missing temp is replaced by that city’s mean temperature (2 places) and missing rain by 0. wettest(df): the (date, city) with the most rain.

Exercise15 points
P5: A rate limiter per client

Write TokenBucket(rate, capacity, clock): it starts full; tokens refill continuously at rate per second up to capacity; allow(cost=1) takes cost tokens and returns True if there are enough, else takes nothing and returns False; retry_after(cost=1) is how many seconds until cost tokens will be available (0 if they already are), rounded to 2 places. Then Limiter(rate, capacity, clock) keeps one bucket per client: check(client) returns (200, None) if allowed, else (429, seconds) with that client’s retry_after().

Part C: a larger program

Exercise30 points
C: A link shortener

Write Shortener(clock, per_minute=5), a link shortener storing links in an in-memory sqlite3 database (table links(id INTEGER PRIMARY KEY, url TEXT, user TEXT, created REAL, clicks INTEGER)), and handling requests with handle(method, path, body), which returns (status, data):

  • POST /links with JSON {"url": ..., "user": ...}: the URL must start with http:// or https:// and both fields must be strings, else 400 with {"error": "bad request"}. If this user already shortened this exact URL, return 200 with the same code; otherwise store it and return 201 with {"code": CODE}. Each user may create at most per_minute new links in any 60 seconds (by clock(); repeats don’t count): beyond that, 429 with {"error": "slow down"}.
  • GET /<code>: 302 with {"location": url}, adding one to its clicks; 404 with {"error": "not found"} for an unknown code.
  • GET /stats/<code>: 200 with {"url", "clicks", "user"}, or 404.
  • Anything else: 404.

A code is the link’s id, plus 10,000, written in base 62 with the digits 0-9, then a-z, then A-Z (so id 1 gives "2Bj"). Use ? parameters for every query.
