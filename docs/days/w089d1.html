Week 89, Day 1

Build

Sprint 2 begins, and its first story is the one sprint 1 kept running into: S7, faster route search. Real footpath maps have thousands of junctions, and Waymark loads the whole map from the database for every request and searches outwards in every direction. Today you’ll measure before optimising (counting the junctions a search finishes, not guessing), give junctions positions so the search can head towards the destination with the A* search, stop reloading the map with a cache that knows when the map has changed, and find the junction nearest to a point with a spatial index. The challenge puts them together: plan a route from wherever the walker is standing.

By the end of today you can

  • Measure an algorithm’s work by counting operations, before and after a change
  • Implement A* search with an admissible straight-line heuristic, and explain why it stays correct
  • Cache expensive loads, and invalidate the cache when the data changes
  • Find the nearest point quickly with a grid index
  • Check the data assumptions an optimisation depends on

waymark_domain.py
import heapq


class UnknownPlace(LookupError):
    pass


class NoRoute(Exception):
    pass


def naismith_minutes(km, climb_m):
    return round(km / 5 * 60 + climb_m / 600 * 60)


class Route:
    def __init__(self, stops, km, climb_m):
        self.stops, self.km, self.climb_m = list(stops), km, climb_m

    @property
    def minutes(self):
        return naismith_minutes(self.km, self.climb_m)

    def __repr__(self):
        return f"Route({self.stops}, {self.km} km, {self.climb_m} m)"


class PathNetwork:
    def __init__(self, heights):
        self.heights = dict(heights)
        self.paths = {name: {} for name in self.heights}

    def _check(self, *names):
        for name in names:
            if name not in self.heights:
                raise UnknownPlace(name)

    def add_path(self, a, b, km):
        self._check(a, b)
        if km <= 0:
            raise ValueError("km must be positive")
        self.paths[a][b] = km
        self.paths[b][a] = km

    def climb(self, stops):
        return sum(max(0, self.heights[b] - self.heights[a]) for a, b in zip(stops, stops[1:]))

    def shortest(self, start, end):
        self._check(start, end)
        dist, prev, done = {start: 0}, {}, set()
        heap = [(0, start)]
        while heap:
            d, node = heapq.heappop(heap)
            if node in done:
                continue
            done.add(node)
            if node == end:
                break
            for nxt, km in sorted(self.paths[node].items()):
                if d + km < dist.get(nxt, float("inf")):
                    dist[nxt] = d + km
                    prev[nxt] = node
                    heapq.heappush(heap, (d + km, nxt))
        if end not in done:
            raise NoRoute(f"no route from {start} to {end}")
        stops = [end]
        while stops[-1] != start:
            stops.append(prev[stops[-1]])
        stops.reverse()
        return Route(stops, round(dist[end], 2), self.climb(stops))

waymark_geo.py
import math
from waymark_domain import PathNetwork
from waymark_map import HEIGHTS, PATHS

POSITIONS = {"Mill": (0.0, 0.0), "Weir": (1.4, 0.4), "Church": (2.8, 1.2), "Ridge": (4.4, 3.4), "Farm": (2.8, 2.4),
             "Wood": (2.0, 3.5), "Lake": (0.6, 2.8), "Island": (-3.0, 5.0)}


class GeoNetwork(PathNetwork):
    """A path network whose junctions also have positions, in kilometres east and north."""

    def __init__(self, heights, positions):
        super().__init__(heights)
        self.positions = dict(positions)

    def straight_km(self, a, b):
        return math.dist(self.positions[a], self.positions[b])


def sample_geo():
    network = GeoNetwork(HEIGHTS, POSITIONS)
    for a, b, km in PATHS:
        network.add_path(a, b, km)
    return network


def grid_network(size):
    """A size-by-size grid of junctions named 'r-c', 1 km apart, with slightly longer paths to their neighbours."""
    names = {(r, c): f"{r}-{c}" for r in range(size) for c in range(size)}
    heights = {name: ((r * 13 + c * 7) % 9) * 20 for (r, c), name in names.items()}
    positions = {name: (float(c), float(r)) for (r, c), name in names.items()}
    network = GeoNetwork(heights, positions)
    for (r, c), name in names.items():
        if c + 1 < size:
            network.add_path(name, names[(r, c + 1)], 1.0 + ((r * 7 + c * 3) % 5) / 10)
        if r + 1 < size:
            network.add_path(name, names[(r + 1, c)], 1.0 + ((r * 3 + c * 5) % 5) / 10)
    return network

Warm-up

Every path is at least as long as the straight line between its ends: you can’t walk from Mill to Ridge in less than 5.4 km, whatever the paths do. That simple fact is what makes today’s faster search correct.

Measure first

“Make it faster” starts with a number. Timing is noisy (other programs, caches, a browser tab), so for algorithms count the work instead: here, how many junctions the search finishes (pops from the heap and expands) before it reaches the destination. Dijkstra’s algorithm finishes every junction closer to the start than the destination, in every direction: to walk a few kilometres east it explores just as far west. On a 30 by 30 grid, from one corner to a junction nearby, that’s 80 junctions to find a route through 13.

Then measure where the time goes in the whole request, not just the algorithm: in Waymark, loading the map from the database for each request turns out to cost far more than the search (Week 65’s profiling). Fix the biggest cost first.

A*: searching towards the goal

A* is Dijkstra’s algorithm with a sense of direction. Instead of always expanding the junction with the smallest distance so far (g), it expands the one with the smallest g + h, where h is an estimate of the distance still to go. With h the straight-line distance to the destination, junctions heading away from it look worse and are left alone.

A* still finds the shortest route if the estimate is admissible: it never overestimates the true remaining distance. The straight line is admissible because no path can be shorter than the straight line between its ends. Overestimate (multiply h by 2, say) and A* gets faster but can return a longer route. The optimisation therefore depends on the data: a path recorded as shorter than the straight line (a typo in the map, or positions in the wrong units) makes h inadmissible. Check that assumption when importing.

Not loading the map every time

The map changes rarely (when someone imports a new one) and is read on every request, which is the perfect case for a cache (Week 81): load it once, keep it in memory, and reuse it. The hard part, as always, is invalidation: after an import, the cached map is stale. Waymark keeps a map_version number in the database that every import increases; the cache remembers which version it holds and reloads only when the number has changed. Checking a number is far cheaper than loading thousands of rows.

Where am I?

To plan “from here”, Waymark needs the junction nearest to a point. Checking every junction works for 8 and is slow for 50,000. A grid index divides the map into square cells and records which junctions are in each; to find the nearest to a point, look in the point’s own cell, then the ring of cells around it, then the next ring, stopping once no unexplored cell could hold anything closer than the best found so far. It’s the same idea as a hash table (Week 44), keyed by position.

Key idea

Measure before optimising, counting work (junctions finished) rather than timing. A* expands the junction with the smallest g + h; with an admissible heuristic (never an overestimate, like the straight-line distance) it still finds the shortest route while exploring less; an overestimate makes it wrong. Check the data supports the heuristic. Cache rarely changing data and invalidate with a version number that every change increases. Find nearest points with a grid index, searching outward ring by ring and stopping when no closer point is possible.

A cache that knows when the map changed

Write MapCache(load, version): load() builds the network (expensive) and version() returns the current map version (cheap). get() returns the cached network, calling load() only the first time and whenever version() differs from the version it was loaded at; it counts loads and hits. clear() empties it, so the next get() loads.

Exercise15 points
The nearest junction

Write GridIndex(positions, cell=1.0): place each junction (name -> (x, y)) in the cell (floor(x / cell), floor(y / cell)). nearest(x, y) returns the name of the junction closest to the point (ties to the alphabetically first), searching ring by ring outward from the point’s cell (ring 0 is the cell itself, ring r the cells exactly r cells away in either direction), and stopping after a ring once the best distance found is at most r × cell (no farther ring can hold anything closer). Count the cells looked at in self.cells_checked (reset on each call). An empty index returns None.

Bug hunt10 points
A faster, longer route

Someone doubled the heuristic to make A* “more decisive”. It is faster, but it no longer finds the shortest route: it prints 13.4. Use the straight-line distance itself, so it prints 13.3.

Bug hunt10 points
Heap entries that can’t be compared

The heap holds (cost, route) pairs. When two costs tie, Python compares the routes, which can’t be ordered, and it crashes with TypeError: '<' not supported. Add a tie-breaker that can always be compared (a counter) between the cost and the route, so it prints ['A', 'B'] ['A', 'C'].
