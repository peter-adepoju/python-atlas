Week 89, Day 5

Code review

This sprint’s pull requests changed algorithms (A*, round walks, a cost function) and added many tests. Reviewing them needs more than last week’s checklist: an algorithm change can be correct and still much slower, a function can grow branches until nobody can follow it, and tests can pass while checking nothing. Today you’ll review complexity (how many paths through a function, measured), documentation and type hints on the public interface, long functions, and the tests themselves, using Python’s ast module to measure what can be measured, so the review conversation is about what can’t. The challenge produces a quality report for a module and its tests.

By the end of today you can

  • Review algorithm changes for correctness, complexity and performance
  • Measure cyclomatic complexity and function length from the syntax tree
  • Check that public functions have docstrings and type hints
  • Recognise test smells that let tests pass without checking anything
  • Combine measurements into a report that guides, not replaces, the review

planner.py
import heapq
import math


def straight_km(positions, a, b):
    """Straight-line distance in km between two junctions."""
    return math.dist(positions[a], positions[b])


def astar(paths, positions, start, end):
    g, prev, done = {start: 0}, {}, set()
    heap = [(straight_km(positions, start, end), start)]
    while heap:
        _, node = heapq.heappop(heap)
        if node in done:
            continue
        done.add(node)
        if node == end:
            stops = [end]
            while stops[-1] != start:
                stops.append(prev[stops[-1]])
            return stops[::-1], g[end]
        for nxt, km in sorted(paths[node].items()):
            if g[node] + km < g.get(nxt, float("inf")):
                g[nxt] = g[node] + km
                prev[nxt] = node
                heapq.heappush(heap, (g[nxt] + straight_km(positions, nxt, end), nxt))
    return None


def describe(stops: list, km: float, minutes: int) -> str:
    """One line for the command-line tool."""
    hours, mins = divmod(minutes, 60)
    return f"{' -> '.join(stops)}: {km:.1f} km, {hours} h {mins:02d} min"


def pick(routes, prefer):
    if prefer == "short" or prefer == "shortest":
        return min(routes, key=lambda r: r["km"])
    elif prefer == "flat" and routes:
        return min(routes, key=lambda r: r["climb"])
    elif prefer == "quiet":
        quiet = [r for r in routes if r["road_km"] == 0]
        if quiet:
            return quiet[0]
        else:
            return min(routes, key=lambda r: r["road_km"])
    return routes[0] if routes else None


def _cache_key(start, end):
    return f"{start}|{end}"
test_planner.py
import random
import time
import pytest
from planner import astar, describe, pick


def test_describe():
    assert describe(["A", "B"], 1.0, 75) == "A -> B: 1.0 km, 1 h 15 min"


def test_astar_runs():
    astar({"A": {"B": 1}, "B": {"A": 1}}, {"A": (0, 0), "B": (1, 0)}, "A", "B")


def test_pick_waits_for_cache():
    time.sleep(0.01)
    assert pick([{"km": 2, "climb": 0, "road_km": 0}], "short")["km"] == 2


def test_pick_errors():
    with pytest.raises(Exception):
        pick([], "flat")["km"]


def test_random_routes():
    rng = random.Random()
    routes = [{"km": rng.random(), "climb": 0, "road_km": 0} for _ in range(5)]
    assert pick(routes, "short")["km"] == min(r["km"] for r in routes)

Warm-up

The syntax tree tells you each function’s size, how many decisions it makes, and whether it explains itself. Open planner.py and test_planner.py above: they’re from this sprint’s pull requests, and they’re what you’ll review today.

Reviewing algorithm changes

For a change to an algorithm, ask, in addition to last week’s list:

  • Is it still correct on the awkward inputs? No route, start equal to end, ties, a disconnected map. The tests from yesterday (oracles, invariants, metamorphic relations, the regression suite) should already say; check they ran.
  • What does it cost? Read the loops: a list membership test or sorted() inside a loop over every junction turns a fast search slow. Ask for the growth test.
  • What does it assume? A* assumes paths are never shorter than the straight line; preferences assume factors of at least 1. Is the assumption written down, and checked?
  • Is the change contained? The search should change in one module; the API and CLI shouldn’t notice.

Measuring complexity

Cyclomatic complexity counts the independent paths through a function: start at 1 and add 1 for each decision (if, elif, for, while, each except, each extra condition in an and or or, each if in a comprehension, and each conditional expression). It’s also the minimum number of tests needed to run every branch. Functions above about 10 are hard to understand and test; pick in planner.py is a candidate. The fix is usually a table instead of a chain of elifs, or smaller functions.

Length matters too: a function over about 30 to 40 lines usually does several things. Both are easy to measure with ast (each node knows its lineno and end_lineno), which means they can be checked in CI and discussed only when they’re exceeded.

The public interface

Functions and classes without a leading underscore are the module’s public interface: other modules (and your future self) rely on them. Each should have a docstring saying what it does (not how), and type hints (Week 33) on its parameters and return value, so readers and tools know what goes in and comes out. Private helpers (_cache_key) can be terser. In planner.py, astar and pick have neither.

Reviewing the tests

Tests deserve review as much as code, because a bad test is worse than none: it gives confidence it hasn’t earned. The usual test smells:

  • No assertion: test_astar_runs only checks that nothing crashed.
  • Sleeping: time.sleep makes tests slow and usually hides a timing dependency that should be injected.
  • Catching everything: pytest.raises(Exception) passes for any error, including a typo; name the exception you expect.
  • Unseeded randomness: random.Random() without a seed gives a different test each run.
  • Testing the mock, and assertions in loops that might run zero times.
Key idea

Review algorithm changes for correctness on awkward inputs, cost (loops inside loops, growth tests), written and checked assumptions, and containment. Measure cyclomatic complexity (1 plus each decision) and length from the syntax tree; flag functions above about 10 branches or 30 to 40 lines, and simplify with tables or smaller functions. Public functions need docstrings and type hints. Review tests for smells: no assertion, sleeps, pytest.raises(Exception), unseeded randomness, testing mocks. Automate the measurements in CI, and spend the review on judgement.

Cyclomatic complexity

Exercise10 points
Long functions

Write function_lengths(source): a dict from each top-level function’s name to its length in lines (from its def line to its last line, using lineno and end_lineno). Then too_long(source, limit=30): the names longer than limit, longest first (ties by name).

Exercise15 points
Test smells

Write test_smells(source) for a test module: a list of (test_name, smell) for top-level functions whose names start with test, in order, with each test’s smells in this order: "no assertion" (no assert statement and no call to pytest.raises); "sleeps" (a call to time.sleep or sleep); "catches everything" (a call to pytest.raises whose first argument is the name Exception or BaseException); and "unseeded random" (a call to random.Random with no arguments).

Bug hunt10 points
A sort that reached the caller

cheapest sorts the list it’s given in place, so the caller’s list of routes changes order behind its back: it prints ['short', 'long'] for the caller’s list, which should still be in its original order. Sort a copy (sorted), so it prints ['long', 'short'].

Bug hunt10 points
Every factor is the last one

The cost functions are made in a loop, and each lambda looks up factor when it’s called, by which time the loop has finished: every one uses 3.0 and it prints [6.0, 6.0]. Bind the current value (a default argument), so it prints [2.0, 6.0].
