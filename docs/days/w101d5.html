Week 101, Day 5

Publish

Teaching material only helps once people can find it. Today you’ll publish this week’s tutorial and explanation as a small static site: Markdown in, HTML out, with a contents list, navigation, a sitemap for search engines, and a check that no link is broken, all from your own code. It’s the course’s own approach in miniature (this course is Markdown turned into a static site by a Python script and served by GitHub Pages), and it’s how most documentation sites work, from a project README to the Python documentation.

By the end of today you can

  • Convert a useful subset of Markdown to escaped HTML
  • Give headings stable anchors and build a contents list
  • Generate navigation and a sitemap
  • Check a site for broken links before publishing
  • Build and check a whole site from a folder of pages

Warm-up

Escaping first means < in the text can’t become a tag; then the Markdown syntax (backticks, brackets) is turned into tags, which are safe because they were added by the converter, not taken from the text. The order matters: escape, then add markup.

Static sites

A static site is a folder of HTML files, built once and served as they are: no server code, no database, nothing to hack or keep running. Generators (MkDocs and Sphinx for documentation, and many more, all free) turn Markdown into HTML with a template. GitHub Pages serves a folder from a repository for free, which is how this course is published. The build is a program like any other, so it can be tested: that every page renders, every link resolves, and every code example runs (Day 1’s checker).

From Markdown to HTML

A small useful subset: headings (#, ##, ###), paragraphs separated by blank lines, fenced code blocks (with a language for highlighting), inline code, and links. Give each heading an anchor (a slug of its text, made unique with -2, -3 for repeats), so a contents list and other pages can link straight to a section. Escape everything that came from the text.

Links that work

Broken links are the commonest fault of documentation sites. Before publishing, collect every href that points inside the site (not starting with http), resolve it against the page it’s on, and check the target exists, and, if it has a #fragment, that the target page has that anchor. A sitemap (sitemap.xml, one <url><loc>...</loc></url> per page) tells search engines what’s there.

Key idea

A static site is a folder of HTML built once from Markdown and served as it is: simple, safe, free to host. Escape the text first, then add markup. Give headings unique slug anchors for contents lists and deep links. Before publishing, check every internal link and fragment resolves, and generate a sitemap. Test the build like any other program.

Practice

Exercise15 points
Markdown to HTML

Write md_to_html(text): lines starting #, ## or ### become <h1> to <h3>; runs of other non-blank lines become one <p> (joined with spaces); a line starting with three backticks opens a code block (the rest of the line is its language, giving class="language-LANG" on <code>) that runs to the next such line and becomes <pre><code ...>ESCAPED</code></pre>. In headings and paragraphs, escape the text (html.escape(..., quote=False)), then turn `code` into <code>code</code> and [text](url) into <a href="URL">text</a>. Join the output elements with newlines.

Exercise10 points
Anchors and contents

Write contents(markdown): for each heading line (# to ###), (level, text, anchor), where the anchor is the text lower-cased with runs of other characters than letters and digits replaced by - and stripped of -, made unique by adding -2, -3, … for repeats.

Exercise10 points
Navigation

Write nav(pages, current): pages is a list of (path, title); return <nav><ul>, an <li><a href="PATH">TITLE</a></li> per page (titles escaped), with aria-current="page" on the current page’s link (<a href="PATH" aria-current="page">), then </ul></nav>, all on one line.

Exercise10 points
A sitemap

Write sitemap(base_url, paths): an XML sitemap: <?xml version="1.0" encoding="UTF-8"?>, <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">, one <url><loc>BASE/PATH</loc></url> per path (sorted; joining base and path with exactly one /, and escaping), and </urlset>, one per line.

Exercise15 points
No broken links

Write broken_links(site): site maps page paths (like "guides/tutorial.html") to their HTML. For every href that doesn’t start with http://, https:// or mailto:, resolve it against the page’s folder (posixpath), and report "PAGE: HREF (missing page)" if the target isn’t in the site, or "PAGE: HREF (missing anchor)" if it has a #fragment that the target has no id="FRAGMENT" for (an href that is only #fragment refers to the same page). Pages in sorted order, links in order.

Bug hunt10 points
Markup that became text

Escaping after adding the <code> tags turns them into text, so the page shows &lt;code&gt; literally: this prints &lt;code&gt;x&lt;/code&gt;. Escape first, then add the tags, so it prints <code>x</code>.

Bug hunt10 points
A link from inside a folder

The link ../index.html on guides/tutorial.html is resolved from the site’s top folder instead of the page’s own folder, so it looks missing and this prints False. Join it with the page’s folder so it prints True.

Daily challenge

Exercise25 points
Challenge: building and checking the site

Write build_site(pages, base_url): pages maps output paths (such as "tutorial.html") to (title, markdown). Using the given md_to_html, build each page as <!DOCTYPE html>, <html lang="en-GB">, <head><meta charset="utf-8"><title>TITLE</title></head>, <body>, the nav of all pages (sorted by path, with an index.html “Home” page first that you generate, listing the pages), the HTML, </body>, </html> (one per line). Give every heading tag an id from the contents anchors (in order: <h2 id="ANCHOR">). Add sitemap.xml. Return (site, problems) where problems is broken_links(site).

Your site

  1. Put your tutorial and explanation (with a link to the video) in a folder of Markdown files.
  2. Build the site with your build_site, or with MkDocs if you prefer, and run the link checker and Day 1’s tutorial checker in the same script.
  3. Publish it with GitHub Pages and link it from your portfolio page (Week 92).
  4. Share it with the learner you mentored, and ask what was unclear.
