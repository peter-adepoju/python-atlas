Week 92, Day 4

Portfolio page

Waymark now has a release, a write-up and a demo. A portfolio page ties them together, alongside your own capstone and earlier projects, so that someone with two minutes can see what you’ve built and follow the links that interest them. It has to work for everyone who visits: on a phone, with a screen reader, with images turned off. Today you’ll generate project cards with properly escaped HTML, then check pages with html.parser for the problems accessibility audits find most often: headings that skip levels, images without alternative text, links that say only “here”, and missing page information. The challenge generates a whole portfolio page that passes every check.

By the end of today you can

  • Decide what a portfolio page needs, and keep it short
  • Generate HTML with every value escaped
  • Scan a page with html.parser for headings, images, links and meta tags
  • Find common accessibility problems automatically
  • Generate a page that passes its own checks

Warm-up

The first line is broken HTML: a browser would read <Junctions> as a tag. Any value that came from data (a project title, a summary, a tag) is escaped before it goes into a page. It’s Week 79’s cross-site scripting lesson again, on your own site.

What the page is for

A visitor to a portfolio has a question (“can this person build things like the ones we build?”) and very little time. Give each project a card: a title, one or two sentences on what it does and for whom, a few tags (Python, pandas, A*), perhaps a screenshot, and links to the code, the demo and the write-up. Put the capstone first. Three to five good projects beat fifteen half-finished ones. Add a short paragraph about yourself and a way to contact you, and nothing else.

Escaping

Generate the page from data (a list of project dicts) rather than writing HTML by hand: it’s easier to keep consistent, and every value passes through one place. html.escape(text) turns &, <, > and both quote marks into entities, so it’s safe inside elements and inside quoted attributes.

Accessible by construction

The Web Content Accessibility Guidelines (WCAG, from the W3C) are long, but most failures on small sites are a handful of things a program can find:

  • Headings form an outline: one h1, then h2 for sections and h3 within them, never skipping a level (screen-reader users jump between headings).
  • Images need alt text that says what the image shows (“Elevation profile of the Ridge walk”). A file name is not a description. Purely decorative images get alt="" so they’re skipped.
  • Links must make sense on their own, since screen readers can list them out of context: “Source code for Waymark”, not “here” or “read more”. A link that opens a new tab with target="_blank" needs rel="noopener".
  • The page needs a language (<html lang="en-GB">), a viewport meta tag so it works on phones, and a meta description of up to about 160 characters for search results and link previews.

html.parser.HTMLParser calls a method for each start tag, end tag and piece of text, which is enough to check all of these. On your own computer, free tools such as axe and Lighthouse check much more.

Publishing

A static page needs no server: GitHub Pages (free for public repositories) serves a folder from a repository, as this course does. Keep the page’s source data in the repository, generate the HTML in CI, run the checks, and publish only if they pass.

Key idea

A portfolio page answers “what can this person build?” quickly: three to five project cards with a summary, tags and links to code, demo and write-up, capstone first. Generate it from data, escaping every value with html.escape. One h1 and no skipped heading levels; alt text that describes (or alt="" for decoration); link text that makes sense alone and rel="noopener" with target="_blank"; lang, a viewport and a description. Check with HTMLParser, publish with GitHub Pages.

Practice

Exercise15 points
A project card

Write project_card(project): project has title, summary, perhaps tags (a list), perhaps image (a dict with src and alt) and perhaps links (a dict with any of code, demo and writeup). Return these lines joined by newlines, escaping every value: <article class="project">; <h3>TITLE</h3>; <img src="SRC" alt="ALT"> if there’s an image; <p>SUMMARY</p>; <ul class="tags"> with <li>TAG</li> for each tag and </ul>, all on one line, if there are tags; <p class="links"> and the links (Source code for TITLE, Demo video of TITLE, Write-up of TITLE, in that order, each <a href="URL">TEXT</a>, separated by spaces) and </p> on one line, if there are links; and </article>.

Exercise15 points
Scanning a page

Write PageScanner(HTMLParser) collecting: headings (a list of heading levels as ints), images (a list of each img’s attributes as a dict), links (a list of (attrs, text) for each a, its text being all the text inside it plus the alt of any image inside it with non-empty alt, with whitespace collapsed to single spaces), lang (the lang of <html>, or None) and meta (a dict from each meta tag’s lower-cased name to its content). Then scan(html) returning a fed, closed scanner.

Exercise10 points
Headings

Using the given scanner, write heading_problems(html): "no h1" if there’s none, or "more than one h1"; then "heading level skips from hA to hB" for each heading more than one level deeper than the one before it.

Exercise15 points
Images and links

Using the given scanner, write image_problems(html): "image SRC has no alt text" for an img with no alt attribute, and "alt text for SRC is a file name" if the alt text ends with .png, .jpg, .jpeg, .gif, .svg or .webp (ignoring case); alt="" is fine. Then link_problems(html), for each link in order: 'link "TEXT" has no href' if href is missing or empty; 'vague link text "TEXT"' if the text (ignoring case) is here, click here, link, read more or more; and "link to HREF opens a new tab without rel=noopener" if target is _blank and noopener isn’t one of the words in rel.

Exercise10 points
Page information

Using the given scanner, write meta_problems(html): in order, "no lang on <html>", "no viewport meta tag", and "no meta description" or, if it’s longer than 160 characters, "description over 160 characters", for each that applies.

Bug hunt10 points
A title that became a tag

The title goes into the page unescaped, so <Junctions> would be read as a tag: it prints <h3>Paths & <Junctions></h3>. Escape it so it prints <h3>Paths &amp; &lt;Junctions&gt;</h3>.

Bug hunt10 points
Click here, missed

The check compares the raw text with lower-case phrases, so neither " Click here " nor "Read more" is caught and this prints []. Compare collapsed, lower-cased text (and report it collapsed), so it prints ['vague link text "Click here"', 'vague link text "Read more"'].

Your capstone today

  1. Write your project data: your capstone first, then two to four earlier projects (Week 25’s spend, the Week 80 helpdesk, a Forge you were proud of), each with a summary, tags and links.
  2. Generate the page with your own build_page, and run today’s checks on it.
