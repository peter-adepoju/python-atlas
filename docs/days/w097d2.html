Week 97, Day 2

Timed DSA set

The second timed set moves from arrays and strings to the structures of Phase 4: binary search on data that’s only partly sorted, graphs hidden in grids and prerequisites, dynamic programming where a greedy answer is wrong, and a heap that keeps a running answer. The method is the same as yesterday; the pattern-spotting is harder, because these problems rarely say “use a graph”. Five problems, sixty minutes, with checks that count your work or time it.

By the end of today you can

  • Spot binary search, graph search, dynamic programming and heaps in disguise
  • Search a rotated sorted list in logarithmic time
  • Explore grids and dependency graphs without recursion limits
  • Choose dynamic programming when greedy fails

Warm-up

Taking the largest coin each time uses three coins (4, 1, 1), but two threes would do. Greedy choices that look right locally can be wrong globally; that’s the signal for dynamic programming.

Disguised structures

  • “Sorted, but…” (rotated, with an unknown length, or a yes/no question that flips once): binary search, O(log n). Decide at each step which half is sorted, or which side the answer lies on.
  • A grid of cells, a map, “connected”, “reachable”: a graph. Explore with breadth-first search and a queue (collections.deque), which has no recursion limit; a deep recursive search on a 300 by 300 grid can exceed Python’s limit of about 1,000 calls.
  • “Prerequisites”, “must come before”, “build order”: a directed graph; a valid order is a topological sort, and a cycle means none exists.
  • “Fewest”, “how many ways”, choices whose effects overlap: dynamic programming: the best answer for amount built from the best answers for smaller amounts.
  • “The k-th largest so far”, “the k closest”: a heap of size k (heapq), O(log k) per item.

The timed set

Exercise15 points
P1: Searching a rotated list

A sorted list of distinct numbers has been rotated ([4, 5, 6, 7, 0, 1, 2]). Write search_rotated(nums, target): the index of target, or -1, in O(log n). The checks pass a list that counts indexing and refuses to be scanned.

Exercise15 points
P2: Counting islands

A map is a list of strings of "1" (land) and "0" (water). Write islands(grid): the number of islands, where land cells joined up, down, left or right belong to the same island. It must handle a 300 by 300 map.

Exercise10 points
P3: Fewest coins

Write fewest_coins(coins, amount): the fewest coins (any number of each value) that make amount, or -1 if it can’t be made.

Exercise15 points
P4: The k-th largest so far

Write a class KthLargest(k, nums) whose add(value) adds a number and returns the k-th largest number seen so far (including nums). There will always be at least k numbers after each add. Each add must take O(log k).

Exercise15 points
P5: An order for the courses

Courses are numbered 0 to n - 1; each (course, before) pair says before must be taken first. Write course_order(n, pairs): an order taking every course after its prerequisites, always choosing the smallest-numbered course available next, or [] if there’s a cycle.

Afterwards

Write down your times and sticking points before reading the models. P1’s two-case logic is easy to get subtly wrong: trace [3, 1] searching for 1. P2 is a reminder that Python’s recursion limit is part of the problem in an interview, and saying so is a good sign.
