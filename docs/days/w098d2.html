Week 98, Day 2

Timed DSA set

The second set of the week is the hardest so far: problems where the right structure isn’t obvious until you’ve tried the obvious one. A heap that tracks when meeting rooms free up; backtracking that explores choices and undoes them; two dynamic programming classics, one with a clever O(n log n) trick; Dijkstra’s algorithm for delays in a network; and, as the challenge, rain trapped between walls in a single pass. As always: method first, timer on, models afterwards.

By the end of today you can

  • Track resources over time with a heap
  • Generate combinations by backtracking without duplicates
  • Solve longest increasing subsequence in O(n log n)
  • Fill an edit-distance table
  • Find shortest delays with Dijkstra’s algorithm

Warm-up

tails[i] is the smallest possible last value of an increasing run of length i + 1 seen so far. Its length is the length of the longest increasing subsequence (here 4, for example 1, 4, 5, 9), found with one binary search per number. The list itself isn’t a subsequence of the input; only its length means anything.

Harder patterns

  • “How many at once?” (rooms, servers, overlapping walks): sort by start and keep a min-heap of end times; the heap’s size at its largest is the answer.
  • “All combinations or arrangements”: backtracking: choose, recurse, un-choose. Avoid duplicates by only choosing candidates from the current index onwards.
  • “Longest increasing…”: the tails trick above, O(n log n), instead of the O(n²) table.
  • “Fewest edits from one string to another”: a table d[i][j] of the edit distance between prefixes, filled from the top left: d[i][j] = d[i-1][j-1] if the characters match, otherwise 1 plus the smallest of the three neighbours. This is Levenshtein distance, after Vladimir Levenshtein.
  • “Shortest time through a weighted network”: Dijkstra’s algorithm with a heap (Phase 4’s Week 49).

The timed set

Exercise15 points
P1: How many rooms?

Meetings are (start, end) with end > start; a room is free again at its meeting’s end time. Write rooms_needed(meetings): the fewest rooms that hold all of them. It must run in O(n log n).

Exercise15 points
P2: Combinations that add up

Write combinations_to(candidates, target): every combination of the (distinct, positive) candidates, each usable any number of times, that adds up to target, each combination in ascending order, the list sorted.

Exercise15 points
P3: The longest increasing run

Write lis_length(nums): the length of the longest strictly increasing subsequence (not necessarily contiguous), in O(n log n).

Exercise15 points
P4: Fewest edits

Write edit_distance(a, b): the fewest single-character insertions, deletions and substitutions that turn a into b.

Exercise15 points
P5: How long until everyone hears?

A message starts at node start in a network of nodes 1 to n; times lists (from, to, delay) for one-way links. Write network_delay(times, n, start): how long until every node has it, or -1 if some never do.

Afterwards

Note your times. P2 is where interviews test whether you can explain recursion while writing it; P3’s trick is worth knowing by heart, along with its O(n²) table as the fallback you’d describe first.

Bug hunt10 points
Duplicate combinations

Each recursive call restarts from the first candidate, so [2, 3, 3], [3, 2, 3] and [3, 3, 2] are all counted, and this prints 4 for target 8 with [2, 3] where the answer is 2 ([2, 2, 2, 2] and [2, 3, 3]). Start from the current candidate so it prints 2.

Bug hunt10 points

A room whose meeting ends at 5 is free for one starting at 5, but < treats them as clashing, and this prints 2. Fix it so it prints 1.
