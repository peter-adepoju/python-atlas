How to use this

Look at your list from yesterday. Do the drills for those topics first, timing yourself: each should take 5 to 10 minutes once you know the move. Then do as many of the others as you have time for. If a drill takes much longer than 10 minutes, go back to its week and redo two exercises there before trying it again.

Structures drills

Each drill names its technique and week. Write the comment line # pattern: ..., cost: ... first.

Exercise10 points
Drill: the shortest window (Week 41)

Positive numbers and a target: write shortest_at_least(nums, target), the length of the shortest stretch with sum at least target, or 0. A window that grows on the right and shrinks on the left while the sum is still enough.

Exercise10 points
Drill: grouping with a dict (Week 44)

Write group_by_letters(words): lists of words that use exactly the same letters the same number of times, each list in the original order, the lists ordered by their first word’s position. Key a dict by the sorted letters.

Exercise10 points
Drill: a calculator stack (Week 43)

Write evaluate(tokens) for an expression in reverse Polish notation (["2", "1", "+", "3", "*"] is (2 + 1) × 3): numbers are pushed; an operator + - * / pops two and pushes the result (/ divides and truncates towards zero, like int(a / b)).

Exercise10 points
Drill: a tree level by level (Week 45)

A tree of nested [value, left, right] lists (None for empty). Write right_side(tree): the value you’d see at each level looking from the right (the last node of each level), with a BFS queue.

Exercise10 points
Drill: merging sorted lists (Week 47)

Write merge_sorted(lists): one sorted list from several sorted lists, with a heap holding one item from each list at a time (O(N log k)), not by sorting everything.

Algorithms drills

Exercise10 points
Drill: fewest moves (Week 50)

A knight on an n × n board: write knight_moves(n, start, goal), the fewest moves from start to goal (both (row, col)), or -1, with BFS.

Exercise10 points
Drill: cheapest path in a grid (Week 51)

Each cell of a grid costs its number to enter (the start cell is free). Moving up, down, left or right, write cheapest(grid): the least cost from the top-left to the bottom-right, with Dijkstra (moves can go in any direction, so Week 53’s grid DP won’t do).

Exercise10 points
Drill: choose, explore, unchoose (Week 52)

Write brackets(n): every balanced string of n pairs of brackets, in sorted order ("(" sorts before ")"), by backtracking that adds ( while fewer than n have been used, and ) while fewer have been closed than opened.

Exercise10 points
Drill: a two-dimensional table (Weeks 53 and 54)

Write common_length(a, b): the length of the longest common subsequence of two strings, with two rows of the table.

Exercise10 points
Drill: subsets by mask (Weeks 54 and 55)

Write best_subset(values, weights, limit): the largest total value of a subset of at most 20 items whose weights add up to at most limit, by trying every mask from 0 to 2ⁿ − 1 (no DP: this drill is about masks).

Edge-case habits

Before pressing Check on any exam problem, run these in your head or in code:

  • Empty input (and a single item).
  • All equal values, and ties: does your tie rule match the question?
  • Boundaries: the first and last positions; k = 0 and k = n; the largest values (and whether an O(n²) solution would time out).
  • Impossible cases: does it return None or -1 as asked, or crash?
  • Mutation: did you change the caller’s list when you shouldn’t?

Daily challenge

Exercise25 points
Challenge: three techniques at once

A delivery robot moves on a grid of "." (floor), "#" (wall), "S" (start) and lower-case letters "a" to "f" (parcels). Each move (up, down, left, right) takes one step. Write collect_all(grid): the fewest steps to pick up every parcel (in any order; the robot needn’t return), or -1. Combine three techniques:

  1. BFS from the start and from each parcel, giving the distances between every pair of important points.
  2. Bitmask DP over the parcels collected, like Held-Karp (Week 54): best[mask][last].
  3. A check for impossibility: if some parcel can’t be reached from the start, return -1 straight away.

Then collect_order(grid): one fewest-step order of parcel letters, as a string.
