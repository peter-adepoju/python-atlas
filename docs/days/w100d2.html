Week 100, Day 2

Weak-spot drills

The second drill day is graphs, the other topic most debriefs flag. As with dynamic programming, the difficulty is mostly recognition and a few standard moves done without hesitation: breadth-first search for fewest steps, a three-colour depth-first search for cycles, two-colouring for “can these be split into two sides?”, Dijkstra’s algorithm with the route remembered, Kruskal’s algorithm for the cheapest network, and the longest path through a plan of tasks. Six drills in rising order, then a challenge that limits the number of stops.

By the end of today you can

  • Turn grids and dependencies into graphs without hesitation
  • Find fewest steps with BFS, and cycles with a three-colour DFS
  • Two-colour a graph, or show it can’t be done
  • Recover Dijkstra’s route as well as its length
  • Build a minimum spanning tree and a critical path

Warm-up

Breadth-first search reaches every cell in order of distance, so the first time it reaches the goal is by a shortest route. Mark cells as seen when you add them to the queue, not when you take them off, or the same cell is queued many times.

Standard moves

  • Fewest steps (unweighted): BFS with a queue and a dist dictionary.
  • Cycle in a directed graph (circular dependencies): depth-first search with three colours: white (unvisited), grey (on the current path), black (finished). Reaching a grey node is a cycle.
  • Two sides (teams, schedules, “no two neighbours alike”): colour by BFS, alternating; an edge between equal colours means it’s impossible.
  • Shortest weighted route: Dijkstra with a heap, remembering each node’s previous node, then walking back from the end.
  • Cheapest network joining everything: Kruskal’s algorithm (Joseph Kruskal, 1956): sort edges by cost and add each one that joins two different groups (union-find from last week).
  • Longest chain of dependent tasks: the critical path: process tasks in topological order, each finishing at its duration plus the latest finish among its dependencies.

Drills

Exercise10 points
Drill 1: Fewest steps past the walls

Write fewest_steps(grid, start, end): the fewest moves (up, down, left, right) through "." cells from start to end (row, column pairs), or -1.

Exercise15 points
Drill 2: A circle of dependencies

Write has_cycle(n, edges): whether the directed graph on nodes 0 to n - 1 with edges (a, b) (a must come before b) contains a cycle, using an iterative three-colour depth-first search (it must handle a chain of 50,000 nodes).

Exercise15 points
Drill 3: Two sides

Walkers who’ve quarrelled (edges of pairs) mustn’t be in the same group. Write two_groups(n, edges): a list giving each walker 0 or 1 (walker 0, and the lowest-numbered walker of each separate part, in group 0), or None if two groups can’t do it.

Exercise15 points
Drill 4: The route, not just its length

Write route(paths, start, end): paths are undirected (a, b, km); return (km, stops) for the shortest route by Dijkstra’s algorithm (km rounded to 2 decimal places), or None if there’s none.

Exercise15 points
Drill 5: The cheapest network of paths

The council will maintain enough paths that every junction is reachable, as cheaply as possible. Write cheapest_network(junctions, paths): (total_km, chosen) by Kruskal’s algorithm (edges sorted by km, then by name pair), chosen the chosen (a, b, km) in the order picked, total rounded to 2 places; None if some junction can’t be reached.

Exercise15 points
Drill 6: The critical path

Preparing a group walk: tasks maps each task to (minutes, [tasks it needs first]). Write critical_path(tasks): (total_minutes, chain) where chain is the longest chain of dependent tasks ending at the task that finishes last (ties by name, earliest finishing dependency chosen by name too). Raise ValueError("cycle") if the tasks depend on each other in a circle.

Bug hunt10 points
Depth first is not fewest steps

Depth-first search finds a route, not the shortest, and here it wanders round the grid and prints 6. Use breadth-first search so it prints 2.

Bug hunt10 points
A network with a loop in it

This adds every short path without checking whether its ends are already joined, so it pays for a loop and prints 5.5 for three junctions where 3.5 is enough. Skip paths that join two junctions already in the same group so it prints 3.5.

Challenge: cheapest with few changes

Buses are one-way (from, to, fare). Write cheapest_with_stops(buses, start, end, max_stops): the cheapest fare from start to end using at most max_stops intermediate stops, or -1. Use Bellman-Ford rounds: relax every bus max_stops + 1 times, each round from a copy of the previous round’s fares.
