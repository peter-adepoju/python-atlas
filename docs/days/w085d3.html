How to review

As before: read, predict each example before running it, then do the exercises without looking back, noting what you had to look up.

The mean (124.8 ms) describes nobody: most requests take about 14 ms, and one in ten takes 240 ms or more. Percentiles describe what users feel. If that surprised you, start with Week 81.

System design

  • Estimate first (Week 81): requests per second from daily users and actions (a day is about 10⁵ seconds), peak as a multiple of average, storage per year, and servers at a safe utilisation (about 70%). Little’s law: requests in progress = arrival rate × time in the system.
  • Caches (LRU, with a time to live) take load off slow stores; the hard part is invalidation (delete or update the cached copy when the data changes) and stampedes (many misses at once).
  • Queues decouple producers from consumers, smooth bursts and allow retries; consumers must be idempotent because messages can arrive twice.
  • Replicas spread reads and survive failures (with replication lag); partitions (shards) spread writes; consistent hashing moves only about 1/n of the keys when a node joins.
  • Distributed systems (Week 82): no shared clock (Lamport and vector clocks order events), majorities (quorums, Raft) agree on one history, and sagas undo multi-step work with compensations.

Every key that moved went to the new node, and only about a quarter moved. With hash(key) % n, most keys would have moved.

Reliability

  • Measure what users feel: rate, errors and duration (RED); percentiles, not averages; traces that follow one request through many services (Week 82).
  • Service level objectives: an SLO such as “99.9% of requests succeed” leaves an error budget of 0.1%; the burn rate is how fast you’re spending it (1 means exactly on budget). Alert on fast burns over short and long windows together.
  • Retries only for transient failures and idempotent operations, with exponential backoff and jitter (so clients don’t retry in step), a cap, and a retry budget. Circuit breakers stop calling a failing dependency and try again after a pause. Deadlines bound the whole request, not each step.
  • Availability multiplies in series (0.999 × 0.999 ≈ 0.998) and improves in parallel (1 − 0.001²).

Data

  • NumPy (Week 83): whole-array operations, broadcasting, boolean masks, axis and keepdims, nan with np.isnan and the nan-functions, seeded default_rng.
  • pandas: read_csv (with dtype=str for messy files), loc and iloc, masks with & and |, new columns with assign, groupby().agg(name=(column, function)), transform, merge(validate=..., indicator=True), pivot_table, to_datetime and resample. Change rows with one .loc, never chained indexing.
  • Cleaning: profile first, never edit the raw file, parse each column deliberately, count and report what you drop.
  • Charts (matplotlib): line for change over time, bar for categories (sorted, from zero), scatter for relationships, histogram for distributions; label everything, with units.

Machine learning

  • The workflow (Week 84): split off a test set first (stratified for classes); build a pipeline (scaling, encoding, model) so preprocessing is fitted on training data only; tune hyperparameters with cross-validation on the training set (GridSearchCV); score on the test set once; compare with a baseline (DummyClassifier).
  • Metrics: accuracy misleads on imbalanced classes; use the confusion matrix, precision (flags that were right) and recall (positives caught), choose the threshold by the costs of each mistake, and ROC AUC to compare rankings; MAE, RMSE and R² for regression.
  • Models: linear and logistic regression (explainable), nearest neighbours (needs scaling), trees and forests (flexible, can overfit), Naive Bayes (text), neural networks (layers, activations, backpropagation, gradient descent); training error far below test error means overfitting.

Classic mistakes

  • Averages instead of percentiles; caches with no invalidation; hash(key) % n sharding; retries on non-idempotent requests, or without jitter.
  • Chained indexing in pandas; joins that duplicate rows; filling missing values with zero before averaging; bars that don’t start at zero.
  • Scaling before splitting; tuning on the test set; reporting accuracy on imbalanced data; judging a model by its training score.
Key idea

Design starts with estimates (rates, peaks, storage, servers at 70%) and uses caches (with invalidation), queues (with idempotent consumers), replicas and partitions (consistent hashing moves about 1/n keys). Reliability is measured with RED and percentiles against SLOs and error budgets, and protected with jittered backoff, retry budgets, circuit breakers and deadlines. Data work uses vectorised NumPy and pandas (groupby, merge with validate, pivot, resample, one .loc for changes), deliberate cleaning, and honest charts. ML splits first, puts preprocessing in a pipeline, tunes by cross-validation, tests once, compares with a baseline, and chooses metrics and thresholds by the cost of each kind of mistake.

Exercise10 points
Back of the envelope

Write estimate(daily_users, reads_per_user, writes_per_user, bytes_per_write, peak_factor, server_qps): a dict with read_qps and write_qps (averages over 86,400 seconds, rounded to whole numbers), peak_qps (reads and writes together, times peak_factor, rounded), gb_per_year (writes × bytes × 365, in units of 10⁹ bytes, rounded to 1 place) and servers (enough to handle peak_qps at 70% of server_qps each, rounded up, at least 2 for redundancy).

Exercise15 points
An LRU cache with expiry

Write TTLCache(capacity, ttl, clock): get(key) returns the value or None (an entry older than ttl seconds, by clock(), counts as missing and is removed), counting hits and misses; put(key, value) stores it (refreshing its age and making it most recently used), evicting the least recently used entry when over capacity; invalidate(key) removes it if present. A successful get makes an entry most recently used.

Exercise15 points
Consistent hashing

Write Ring(nodes, vnodes=50), placing each node at the points zlib.crc32(f"{node}#{i}".encode()) for i in range(vnodes). node_for(key) returns the node at the first point at or after the key’s hash (zlib.crc32(key.encode())), wrapping round to the first point. add(node) and remove(node) change the ring. Then moved(keys, before, after): how many keys map to a different node in after than in before.

Exercise10 points
Retrying politely

Write call_with_retry(call, attempts, base, cap, rng, sleep): call call(); if it raises TransientError (given), sleep for a full-jitter delay, rng.uniform(0, min(cap, base × 2^k)) for the k-th retry (from 0), and try again, up to attempts calls in all, then re-raise the last error. Any other exception is raised at once, without retrying. Return the call’s result.

Exercise15 points
Endpoint statistics

Write endpoint_stats(df) for the request log (columns time, method, endpoint, status, ms): a list of dicts, one per endpoint, sorted by p95 from slowest (ties by name), with endpoint, requests, error_rate (the fraction with status 500 or above, 3 places) and p95 (the nearest-rank 95th percentile of ms: the value at position ceil(0.95 × n) in sorted order, counting from 1). Then errors_by_hour(df): a dict from hour (an int) to the number of errors, for every hour in the log.

Exercise15 points
A tuned, honest model

Write tuned_model(X, y, seed=0): split 75/25 stratified with random_state=seed; tune a pipeline of StandardScaler and LogisticRegression(max_iter=2000) over C in [0.01, 0.1, 1, 10] with GridSearchCV(..., cv=5) on the training data only; return a dict with best_C, cv_score (3 places), test_score (3 places) and baseline (a most-frequent DummyClassifier’s test accuracy, 3 places).

Bug hunt10 points
A price that never changes

The price is updated in the database, but the cache still holds the old one, so the page keeps showing it: price: 10. Invalidate the cached copy when the price changes, so it prints price: 12.

Bug hunt10 points
A percentile off by one

The nearest-rank 95th percentile of twenty values is the 19th smallest (position ceil(0.95 × 20) = 19, counting from 1). Indexing with int(0.95 * n) treats that as a position counting from 0, so it picks the 20th: p95: 900. Use ceil(0.95 × n) − 1 as the index, so it prints p95: 240.

Bug hunt10 points
A model scored on its homework

The model is scored on the data it was trained on, so a one-neighbour classifier looks perfect: score: 1.0. Score it on the held-out test set instead, so it prints score: 0.711.

Exercise25 points
Challenge: a service health report

Write health_report(path, slo=0.99) for a request log like requests.csv. Return (report, fig). The report has: per_endpoint (as endpoint_stats from the exercises: dicts with endpoint, requests, error_rate and nearest-rank p95, slowest first); availability (the fraction of all requests with status below 500, 4 places); budget_used (the error fraction divided by 1 − slo, 2 places); verdict ("over budget" if budget_used is above 1, else "ok"); worst_hour (the hour with most errors, ties to the earliest; None if there are none); and cache_candidates (sorted endpoints served by GET with at least 10 requests and a p95 above 100 ms). The figure has two axes side by side: a bar chart of each endpoint’s p95, slowest first, titled "p95 latency" with y label "ms"; and a line of requests per hour (every hour from the first to the last in the log), titled "Requests per hour".
