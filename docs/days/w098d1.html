Week 98, Day 1

Timed DSA set

This week’s first set is about the structures interviewers love because they’re small enough to draw: linked lists and binary trees. They test whether you can keep several references straight without losing a node, and whether you can think recursively and iteratively. nodes.py gives you ListNode, TreeNode and helpers to build and print them. Five problems in sixty minutes, then a challenge: turning a tree into a string and back.

By the end of today you can

  • Rewire linked lists without losing nodes
  • Detect a cycle with two pointers in constant space
  • Traverse trees by depth and by level
  • Use the binary search tree property with bounds
  • Serialise and rebuild a tree

nodes.py
class ListNode:
    def __init__(self, value, next=None):
        self.value, self.next = value, next


class TreeNode:
    def __init__(self, value, left=None, right=None):
        self.value, self.left, self.right = value, left, right


def make_list(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head


def to_list(head, limit=10_000):
    out = []
    while head is not None and len(out) < limit:
        out.append(head.value)
        head = head.next
    return out


def make_tree(values):
    """Build a tree from level order, with None for missing children."""
    if not values or values[0] is None:
        return None
    root = TreeNode(values[0])
    queue, i = [root], 1
    while queue and i < len(values):
        node = queue.pop(0)
        for side in ("left", "right"):
            if i < len(values) and values[i] is not None:
                child = TreeNode(values[i])
                setattr(node, side, child)
                queue.append(child)
            i += 1
    return root

Warm-up

make_tree reads a tree in level order, with None for a missing child: 5 at the root, 3 and 8 below it, then 3’s children (none on the left, 4 on the right). That’s how interview problems usually write trees, so it’s worth being able to read it at a glance.

Pointers and trees

Linked lists: draw the boxes and arrows before coding, and name every reference you need (previous, current, following). Most bugs are a lost next because it was overwritten before it was saved. Two pointers moving at different speeds (Robert Floyd’s “tortoise and hare”) find the middle of a list or a cycle in O(1) extra space.

Trees: depth-first (recursive, or a stack) for questions about paths and depths; breadth-first with a queue for questions about levels. A binary search tree keeps every value in the left subtree smaller and every value in the right larger, which is a property of the whole subtree, not just a node’s children: pass the allowed bounds down as you go.

Recursion depth: a tree of 100,000 nodes in a line is 100,000 calls deep. Say so in the interview, and use an explicit stack when it matters.

P2: Where does the cycle start?

Write cycle_start(head): the node where a cycle begins, or None if the list ends. Use two pointers (O(1) extra space).

Exercise15 points
P3: Level by level

Write levels(root): the values of a binary tree level by level, as a list of lists, left to right.

Exercise15 points
P4: Is it a search tree?

Write is_bst(root): whether every node’s value is greater than all values in its left subtree and less than all in its right subtree. It must handle a tree 50,000 levels deep.

Exercise15 points
P5: The lowest common ancestor

In a binary search tree, write common_ancestor(root, a, b): the value of the lowest node that has both values a and b in its subtree (a node counts as its own descendant). Both values are in the tree. Use the search tree property: O(height).

Afterwards

Note your times and stumbles. P4’s classic mistake is checking only a node’s children (the second test case), and P2’s is proving to yourself why the second phase finds the start: draw it.

A list that lost its tail

This overwrites current.next before saving it, so the walk stops after one node and prints [1]. Save the next node first, so it prints [3, 2, 1].

Bug hunt10 points
Checking only the children

Each node here is larger than its left child and smaller than its right one, but 6 sits in 5’s left subtree, so this isn’t a search tree; checking only children prints True. Check bounds for whole subtrees so it prints False.
