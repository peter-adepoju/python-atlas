The method

Interviewers want to see how you think as much as whether you finish. A method keeps you calm and shows your thinking:

  1. Clarify (2 minutes): restate the problem; ask about input sizes, empty inputs, duplicates, negative numbers, what to return when there’s no answer.
  2. Examples: work one small example by hand, and one edge case. Say them aloud.
  3. A simple solution first: describe the brute force and its complexity (“checking every pair is O(n²)”). It proves you understand the problem, and it’s a fallback.
  4. Improve it: what work is repeated? Could a dictionary, a sort, two pointers or a window remove it? Say the new complexity before coding.
  5. Code it cleanly, talking as you go: good names, small helper functions.
  6. Test by tracing your example through the code, then the edge cases. Find your own bugs before the interviewer does.
  7. Complexity: time and space, with a reason.

If you’re stuck, say what you’re thinking; interviewers give hints to people who show their reasoning.

Patterns to look for

  • “Find a pair (or a complement)”: a dictionary of what you’ve seen, O(n).
  • “Longest or shortest stretch with a property”: a sliding window with two indices.
  • “Sorted input” or “pairs from both ends”: two pointers.
  • “Matching, nesting, most recent first”: a stack.
  • “Overlapping ranges”: sort by start, then sweep.
  • “Top k” or “most frequent”: count, then sort or use a heap.

The timed set

Five problems, sixty minutes. Each has checks for correctness and a check that a large input runs quickly, so a brute force won’t pass. Start the timer, and don’t open hints or solutions until it ends.

Exercise10 points
P1: A pair with a sum

Write pair_with_sum(nums, target): return (i, j) with i < j and nums[i] + nums[j] == target, choosing the pair whose j is smallest (and for that j, the smallest i), or None if there’s none. It must run in linear time.

Exercise15 points
P2: The longest stretch without repeats

Write longest_unique(s): the length of the longest substring of s with no repeated character. It must run in linear time.

Exercise10 points
P3: Balanced brackets

Write balanced(s): whether every (, [ and { in s is closed by the matching bracket in the right order (other characters are ignored).

Exercise15 points
P4: Merging overlapping walks

Walks on a route are (start_km, end_km) intervals, in any order. Write merge_intervals(intervals): merge every overlapping or touching pair and return the merged intervals sorted by start. It must run in O(n log n).

Exercise15 points
P5: The most frequent words

Write top_words(words, k): the k most frequent words, most frequent first, ties in alphabetical order.

Afterwards

Before reading the model answers, write down for each problem: how long it took, where you got stuck, and the complexity of your solution. Then compare. The usual lessons: clarifying edge cases first saves debugging later (P2’s "abba" catches windows that move backwards), and the pattern names above are worth learning by heart.

Bug hunt10 points
A window that moved backwards

In "abba", the second a was last seen at index 0, before the window starts, but this moves start back to 1 and reports 3. Only move start forwards, so it prints 2.
