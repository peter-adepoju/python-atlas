Week 88, Day 6

Sprint review

The first build sprint ends. A sprint review answers three questions honestly: what was built (shown working, not described), how the sprint went by the numbers (what was finished, how the work burned down, what’s carried over, and what that says about the next sprints), and what changes next time. Today you’ll build the tools that make the review quick and truthful: a sprint report that computes velocity, the burndown and a forecast and writes the release notes, and, as the bonus, a demo script that checks itself, so the demo you show is the program actually running.

By the end of today you can

  • Show finished work as a working demo, and keep the demo honest by running it as a test
  • Measure a sprint: points done, the burndown, carry-over and velocity history
  • Forecast the rest of the backlog as a range, and adjust the plan
  • Release the sprint’s work with a version and changelog
  • Run a retrospective that changes the next sprint

waymark_domain.py
import heapq


class UnknownPlace(LookupError):
    pass


class NoRoute(Exception):
    pass


def naismith_minutes(km, climb_m):
    return round(km / 5 * 60 + climb_m / 600 * 60)


class Route:
    def __init__(self, stops, km, climb_m):
        self.stops, self.km, self.climb_m = list(stops), km, climb_m

    @property
    def minutes(self):
        return naismith_minutes(self.km, self.climb_m)

    def __repr__(self):
        return f"Route({self.stops}, {self.km} km, {self.climb_m} m)"


class PathNetwork:
    def __init__(self, heights):
        self.heights = dict(heights)
        self.paths = {name: {} for name in self.heights}

    def _check(self, *names):
        for name in names:
            if name not in self.heights:
                raise UnknownPlace(name)

    def add_path(self, a, b, km):
        self._check(a, b)
        if km <= 0:
            raise ValueError("km must be positive")
        self.paths[a][b] = km
        self.paths[b][a] = km

    def climb(self, stops):
        return sum(max(0, self.heights[b] - self.heights[a]) for a, b in zip(stops, stops[1:]))

    def shortest(self, start, end):
        self._check(start, end)
        dist, prev, done = {start: 0}, {}, set()
        heap = [(0, start)]
        while heap:
            d, node = heapq.heappop(heap)
            if node in done:
                continue
            done.add(node)
            if node == end:
                break
            for nxt, km in sorted(self.paths[node].items()):
                if d + km < dist.get(nxt, float("inf")):
                    dist[nxt] = d + km
                    prev[nxt] = node
                    heapq.heappush(heap, (d + km, nxt))
        if end not in done:
            raise NoRoute(f"no route from {start} to {end}")
        stops = [end]
        while stops[-1] != start:
            stops.append(prev[stops[-1]])
        stops.reverse()
        return Route(stops, round(dist[end], 2), self.climb(stops))
waymark_map.py
from waymark_domain import PathNetwork

HEIGHTS = {"Mill": 40, "Weir": 55, "Church": 80, "Ridge": 310, "Farm": 120, "Wood": 150, "Lake": 60, "Island": 5}
PATHS = [("Mill", "Weir", 1.5), ("Weir", "Church", 2.0), ("Mill", "Church", 4.0), ("Church", "Ridge", 3.0),
         ("Weir", "Farm", 2.5), ("Farm", "Ridge", 2.0), ("Farm", "Wood", 1.5), ("Wood", "Lake", 2.0), ("Lake", "Mill", 3.5)]


def sample_network():
    network = PathNetwork(HEIGHTS)
    for a, b, km in PATHS:
        network.add_path(a, b, km)
    return network
cli.py
import argparse
import contextlib
import io
from waymark_domain import NoRoute, UnknownPlace
from waymark_map import sample_network


def main(argv, out):
    parser = argparse.ArgumentParser(prog="waymark")
    sub = parser.add_subparsers(dest="command", required=True)
    p = sub.add_parser("plan")
    p.add_argument("start")
    p.add_argument("end")
    try:
        with contextlib.redirect_stderr(io.StringIO()):
            args = parser.parse_args(argv)
    except SystemExit:
        out.write("usage: waymark plan START END\n")
        return 2
    try:
        route = sample_network().shortest(args.start, args.end)
    except UnknownPlace as e:
        out.write(f"unknown place: {e.args[0]}\n")
        return 2
    except NoRoute as e:
        out.write(f"{e}\n")
        return 1
    hours, minutes = divmod(route.minutes, 60)
    out.write(f"{' -> '.join(route.stops)}: {round(route.km, 1)} km, {hours} h {minutes:02d} min\n")
    return 0

The review

A sprint review has three parts, about an hour in all (shorter alone, but don’t skip it):

  1. The demo. Show each finished story working, from the user’s side: the command, the request, the screen. Only finished stories (Week 87’s definition of done) appear; “nearly done” is carried over, not demonstrated. The safest demo is one you’ve run as a test: a script of commands and their expected output, checked automatically, so the demo can’t drift from the program. That’s the bonus.
  2. The numbers. Points finished (this sprint’s velocity), what’s carried over and why, the burndown’s shape (a late cliff means stories were too big to finish one at a time), and the forecast for the rest of the backlog as a range from your slowest to your fastest sprint. With two sprints left in the capstone’s build phase, the forecast tells you now whether the musts will fit, while there’s still time to cut.
  3. The retrospective (Week 87): what went well, what didn’t, one to three actions for the next sprint, and whether last sprint’s actions happened.

Then release what’s done: a version from the commits (Week 87, Day 4), a changelog entry, and a tag. A release at the end of every sprint keeps the project always shippable.

Exercise50 points
Sprint report

Write sprint_report(name, planned, done_on, days, history, backlog_points, version, messages, date) using the given helpers. planned maps story ids to points; done_on gives finishing days; history is the velocity of earlier sprints; backlog_points counts the points still in the backlog excluding carried-over stories; version is the current release; messages are the sprint’s commit messages. Return a dict with velocity (points done), history (the old history plus this sprint), carried, remaining (the burndown list), forecast (from forecast with the new history, for the backlog plus the carried points), release (the new version, or None if nothing to release) and text, the review written exactly like this (lines in this order):

# NAME review
Done: S3, S6, S8 (6 points)
Carried over: S5 (5 points)
Burndown: 11 11 8 6 6 5
Velocity: 6 (average of last 3: 7.0)
Forecast for 25 points: 4 sprints (best 4, worst 5)
Release: 0.2.0

where Done: and Carried over: say none (0 points) when empty, the worst case is unknown when the slowest recent sprint finished nothing (the given forecast returns None for it), the average comes from velocity(new_history), and the release line says Release: nothing to release when there’s none.

Reading Waymark’s first sprint

Six points done out of eleven, and the burndown was flat for the first day and the last two: S5, the walk log, was the biggest story and never finished, because it was started on Monday alongside S3 rather than after it. The forecast now says four sprints for 25 points, with two build sprints left. That’s the most useful sentence in the review: something must be cut now. For Waymark, S10 (exporting routes) moves to “won’t have this time”, and next sprint finishes S5 before starting anything else. What does your forecast say, and what will you cut?

Bonus: a demo that checks itself

A demo that’s typed live goes wrong in front of people; one that’s described (“and then it would show…”) proves nothing. The fix is a demo script: the commands you’ll show and exactly what each prints, kept in the repository and run as a test in CI, like a golden file for the whole user experience. If the program changes, the test fails, and the demo is updated deliberately. It doubles as documentation: the README’s usage section can be the same file. (Python’s doctest does the same for examples in docstrings.)

Exercise30 points
Bonus: a demo that checks itself

demo.txt (a page file) is a demo script: each step is a line starting with $ (the command), then the expected output lines, then optionally [exit N] (otherwise the exit code must be 0). Write parse_demo(text): a list of (command, expected_output, expected_code), where expected_output is the output lines joined with newlines and ending with one newline (or "" if none). Then run_demo(steps, main): run each step with the page’s cli.main(argv, out) style function (argv is the command split on spaces, without the leading waymark) and return a list of report lines: PASS N: COMMAND, or FAIL N: COMMAND followed by : expected exit E, got G if the code differs, else : output differs. And demo_ok(report): whether every line passes.
