Before you start

The rules. You have 2 hours and 50 minutes in total. Work alone. Close your notes, don’t use the tutor, and don’t search the web: the point is to find out what you can do, and the debrief can only help with gaps it can see. You may run your code and use Check my answer as often as you like.

Count a problem’s full marks only when every check passes. 108 (60%) passes Phase 6; 144 (80%) is a distinction. If you don’t pass, tomorrow’s debrief tells you what to revise, and you can take the exam again after the rest week.

Part B: eight problems

Exercise10 points
B1: Tests for shipping costs

shipping.py has cost(weight_kg, express=False): parcels up to and including 2 kg cost £3.50, up to and including 10 kg £7.00, and heavier ones £7.00 plus £1.00 for every started kilogram over 10 (so 10.2 kg costs £8.00); express doubles the price; a weight of zero or less raises ValueError. Write tests that pass on this code and catch all six broken versions.

shipping.py
import math

def cost(weight_kg, express=False):
    if weight_kg <= 0:
        raise ValueError("weight must be positive")
    if weight_kg <= 2:
        price = 3.50
    elif weight_kg <= 10:
        price = 7.00
    else:
        price = 7.00 + math.ceil(weight_kg - 10) * 1.00
    return price * 2 if express else price

B2: Predict

Work out each value without running anything, then fill them in.

Exercise10 points
B3: Resolving dependencies

Write resolve(available, requirements). available maps package names to lists of version strings ("MAJOR.MINOR.PATCH"); requirements is a list of (name, spec) pairs, where a package may appear more than once and spec is one or more comma-separated clauses: ^X.Y.Z (at least that, below the next major), >=, < and ==. Return a dict from each required package to the highest version satisfying all its specs, or raise ValueError("no version of NAME") if none does or the package isn’t available.

Exercise15 points
B4: Signing up for events

With the given make_db(), write sign_up(conn, event_id, person): in one transaction, add a signup with status "booked" if the event has fewer booked people than its capacity, otherwise "waiting"; a person already signed up (in either status) gets ValueError("already signed up"); return the status. cancel(conn, event_id, person): remove their signup (ValueError("not signed up") if none) and, if they were booked, move the earliest waiting person (lowest signup id) to booked, in the same transaction; return that person’s name or None. summary(conn): (title, booked, waiting) for every event, by title, counting zeros too.

Exercise15 points
B5: Conditional requests

Write respond(method, path, headers, pages) for a tiny read-only site whose pages dict maps paths to body text. Header names are case-insensitive. Return (status, response_headers, body):

  • An unknown path: 404, {}, "not found".
  • A known path with a method other than GET or HEAD: 405, {"Allow": "GET, HEAD"}, "".
  • Otherwise, the page’s ETag is '"' + sha256(body).hexdigest()[:16] + '"' (UTF-8 bytes). If the request’s If-None-Match header equals it, 304 with just {"ETag": ...} and an empty body. Else 200 with headers ETag, Content-Type: text/plain; charset=utf-8 and Content-Length (the body’s byte length), and the body; for HEAD, the same status and headers but an empty body.
Exercise15 points
B6: Password-reset tokens

Write ResetTokens(clock, make_token, ttl=900). issue(user) calls make_token() (which returns a random string) and stores only its SHA-256 hex digest, with the user and an expiry ttl seconds from now; it returns the token itself (to be emailed). Issuing again for the same user replaces their previous token. redeem(token) returns the user and makes the token unusable, or raises ValueError("invalid token") for a token that is unknown, already used, replaced or expired (now >= expiry). Compare digests with hmac.compare_digest. Never store the token itself.

Exercise15 points
B7: Sales by category

sales.csv and products.csv are shown above. Write revenue_table(sales, products): join each sale to its product (every sale kept; a duplicated product row must raise an error), compute revenue (qty × price), and return a pivot as a dict of dicts: months ("2026-01") to categories to revenue rounded to 2 places, with 0 where a category sold nothing that month. Then best_sellers(sales, products): a dict from each category to the name of its product with the highest total revenue.

Exercise20 points
B8: Choosing k honestly

Write choose_k(X, y, ks, folds=5): estimate each k’s accuracy for a pipeline of StandardScaler and KNeighborsClassifier(n_neighbors=k) by your own k-fold cross-validation: split the row positions, in order, into folds consecutive parts whose sizes differ by at most one (larger parts first); train on the others and score on each part. Return (best_k, scores), where scores maps each k to its mean accuracy rounded to 3 places and best_k has the highest mean (ties: the smallest k). Then evaluate(X_train, y_train, X_test, y_test, k): fit the pipeline with that k on the training data and return a dict with test accuracy, precision and recall for class 1 (3 places).

Part C: a larger program

Exercise50 points
C: A metrics service

Write Metrics(api_keys, clock), a small service that collects request measurements from other services and reports on them. api_keys maps secret keys to service names. Store events in an in-memory sqlite3 table (events(service TEXT, endpoint TEXT, status INTEGER, ms REAL, at REAL)) using ? parameters. handle(method, path, headers, body) returns (status, data); header names are case-insensitive, and path may include a query string.

  • Authentication. Every request needs an X-Api-Key header matching one of the keys (check each with hmac.compare_digest); otherwise 401 with {"error": "bad key"}. Events and reports belong to the key’s service: one service never sees another’s data.
  • POST /events with a JSON list of events, each a dict with endpoint (a string starting with /), status (an integer from 100 to 599) and ms (a number, at least 0; not a boolean). If the body isn’t a JSON list, 400 with {"error": "bad request"}; if event number i (from 0) is invalid, 400 with {"error": "bad event i"} and nothing is stored. Otherwise store them all with at = clock() and return 202 with {"accepted": n}.
  • GET /summary, with optional query parameters endpoint (only that endpoint) and window (seconds, default 3600; only events with at > now − window): 200 with {"count", "error_rate", "p95", "slowest"}: the number of events, the fraction with status 500 or more (3 places), the nearest-rank 95th percentile of ms (None if there are no events) and the endpoint with the highest p95 (ties: alphabetical first; None if none).
  • GET /slo with an optional target (default 0.99), over the default window: 200 with {"availability", "budget_used", "status"}: availability is the fraction of events below 500 (4 places; 1.0 if there are none), budget_used is the error fraction divided by 1 − target (2 places), and status is "ok" if budget_used is at most 0.5, "burning" if at most 1, else "exhausted".
  • Known paths with the wrong method give 405 with {"error": "method not allowed"}; unknown paths 404 with {"error": "not found"}.
