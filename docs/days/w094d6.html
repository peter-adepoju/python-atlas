Review

REPO = {
"README.md": '''# pathkit

Small path-finding helpers: a graph, shortest routes, CSV loading.

    python -m pathkit.cli map.csv a c
''',
"pathkit/__init__.py": '''"""A small library of path-finding helpers."""
from pathkit.graph import Graph
from pathkit.search import shortest

__all__ = ["Graph", "shortest"]
''',
"pathkit/graph.py": '''class Graph:
    """An undirected graph with a cost on each edge."""

    def __init__(self):
        self.edges = {}

    def add(self, a, b, cost):
        self.edges.setdefault(a, {})[b] = cost
        self.edges.setdefault(b, {})[a] = cost

    def neighbours(self, node):
        return sorted(self.edges.get(node, {}).items())


def from_pairs(pairs):
    graph = Graph()
    for a, b, cost in pairs:
        graph.add(a, b, cost)
    return graph
''',
"pathkit/search.py": '''import heapq

from pathkit.graph import Graph


def shortest(graph, start, end):
    heap, seen = [(0, start, [start])], set()
    while heap:
        cost, node, path = heapq.heappop(heap)
        if node == end:
            return cost, path
        if node in seen:
            continue
        seen.add(node)
        for nxt, step in graph.neighbours(node):
            heapq.heappush(heap, (cost + step, nxt, path + [nxt]))
    return None


def reachable(graph, start):
    found, todo = {start}, [start]
    while todo:
        for nxt, _ in graph.neighbours(todo.pop()):
            if nxt not in found:
                found.add(nxt)
                todo.append(nxt)
    return found
''',
"pathkit/io.py": '''import csv

from pathkit.graph import from_pairs


def load_csv(path):
    with open(path, newline="") as f:
        rows = [(a, b, float(cost)) for a, b, cost in csv.reader(f)]
    return from_pairs(rows)
''',
"pathkit/cli.py": '''import sys

from pathkit.io import load_csv
from pathkit.search import shortest


def main(argv=None):
    argv = sys.argv[1:] if argv is None else argv
    graph = load_csv(argv[0])
    result = shortest(graph, argv[1], argv[2])
    if result is None:
        print("no route")
        return 1
    cost, path = result
    print(" to ".join(path), cost)
    return 0
''',
"tests/test_graph.py": '''from pathkit.graph import Graph, from_pairs


def test_add_is_symmetric():
    g = Graph()
    g.add("a", "b", 2)
    assert g.neighbours("b") == [("a", 2)]


def test_from_pairs():
    g = from_pairs([("a", "b", 1), ("b", "c", 2)])
    assert g.neighbours("b") == [("a", 1), ("c", 2)]
''',
"tests/test_search.py": '''from pathkit.graph import from_pairs
from pathkit.search import shortest


def test_shortest():
    g = from_pairs([("a", "b", 1), ("b", "c", 2), ("a", "c", 5)])
    assert shortest(g, "a", "c") == (3, ["a", "b", "c"])

Warm-up

Mixed review

Exercise10 points
Which tests does a change affect?

Write affected_tests(graph, module): graph maps each module to the modules it imports. Return, sorted, the test modules (names starting with tests. or whose last part starts with test_) that import module directly or through other modules.

Exercise10 points
Reading a NEWS file name

Write parse_news_path(path) for paths like Misc/NEWS.d/next/Library/2026-11-20-14-03-12.gh-issue-140123.AbCdEf.rst: return a dict with section, when (a datetime), issue (an int) and nonce. Raise ValueError("not a NEWS entry: PATH") if it doesn’t match.

From issue to plan

A first contribution goes better with a plan written before any code: where the code is (search and definitions), what else uses it (callers, so you know what might break), which tests cover it (the test modules that import it, directly or not), what kind of change it is (bug, docs, feature), and so where the NEWS entry goes and which branches it belongs on. Each of those is a tool from this week. Put them together and you have the first comment of a good pull request description.

Exercise50 points
A contribution plan

Write contribution_plan(repo, issue, branches). repo maps paths to sources (like REPO); issue has number, title and labels; branches maps versions to statuses. Return a list of lines:

  1. "names: ...": the words in the title that are defined in the repository, in title order without repeats. A word is a match for [A-Za-z_][A-Za-z0-9_.]*; it’s defined if it, or its last dotted part, is a key of the definitions index (functions, classes and Class.method, as on Day 1). Use the key that matched;
  2. "defined in: ...": every PATH:LINE for those names, in order, without repeats;
  3. "called by: ...": the callers (Day 1’s rule, by the name’s last dotted part) of each name, in order, without repeats;
  4. "tests to run: ...": the test modules affected by the modules those names are defined in, sorted, without repeats;
  5. "kind: KIND": docs if the labels include docs, feature if type-feature, security if type-security, otherwise bug;
  6. "news section: SECTION": Documentation for docs, Security for security, Library otherwise;
  7. "backports: ...": Day 3’s labels for the kind.

Write none for any empty list.

Before writing any code

The plan for issue 77 shows something worth noticing: Graph.add is called from from_pairs and the tests, but the tool also lists shortest and reachable, which call set.add, not Graph.add. A real plan reads each caller before trusting it. What would you check first, and which test would you write before touching shortest?
