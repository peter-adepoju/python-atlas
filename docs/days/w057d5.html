Week 57, Day 5

DSA exam

This is the end of Phase 4. The exam checks that you can use what you’ve learned in Weeks 41 to 56 on your own: a quiz on the ideas, eight problems, and one larger program. It’s marked by the same checks as every exercise, but there are no hints and no solutions until tomorrow’s debrief. Take it honestly: it’s for you.

By the end of today you can

  • Show you can choose and use the right data structure for a problem
  • Show you can apply graph, greedy, backtracking and DP techniques to new problems
  • Show you can reason about costs and edge cases under time pressure
  • Show you can combine structures in a larger program

Before you start

The rules. You have 2 hours and 50 minutes in total. Work alone. Close your notes, don’t use the tutor, and don’t search the web: the point is to find out what you can do, and the debrief can only help with gaps it can see. You may run your code and use Check my answer as often as you like.

The marks.

Part What Marks
A 20 quiz questions 20 (1 each)

Count a problem’s full marks only when every check passes. 108 (60%) passes Phase 4; 144 (80%) is a distinction. If you don’t pass, tomorrow’s debrief tells you what to revise, and you can take the exam again after the rest week.

Strategy. Read every problem first and write the pattern for each. Do the ones you’re sure of first, and don’t stay stuck on one for more than 20 minutes. Test small and awkward cases before pressing Check.

Part B: eight problems

Exercise10 points
B1: The most common

Write top_k_frequent(nums, k): the k values that appear most often, most frequent first, ties broken by the smaller value, in O(n log k) with a heap (or O(n) with buckets).

Exercise10 points
B2: Mending brackets

Write fewest_insertions(s): the fewest brackets to insert anywhere into a string of "(" and ")" to make it balanced. One pass, counting open brackets still waiting and closing brackets that had nothing to close.

Exercise10 points
B3: Predict

Replace each ___ with the value the comment describes. Don’t run the code fragments; work them out.

Exercise15 points
B4: An unknown alphabet

A list of words is sorted in the order of an unknown alphabet. Write alphabet_order(words): the letters in an order consistent with the list, choosing the alphabetically smallest available letter at each step (Kahn’s algorithm with a heap), or None if the list can’t be sorted in any alphabet (a cycle, or a word before its own prefix, like "abc" before "ab"). Every letter in the words must appear.

Exercise15 points
B5: Tasks with a cool-down

A machine runs one task per time slot. Tasks are letters; two runs of the same letter must be at least n + 1 slots apart (n idle-or-other slots between them). Write least_slots(tasks, n): the fewest slots to run them all, and schedule(tasks, n): one such schedule as a string, with "." for idle slots, built greedily: at each slot run the available letter with the most runs left (alphabetically first on a tie).

Exercise15 points
B6: The longest balanced stretch

Write longest_balanced(s): the length of the longest substring of "(" and ")" that is a balanced bracket string, in O(n): a stack of indices, starting with −1 as the base before the current stretch.

Bug hunt15 points
B7: Three bugs

first_at_least(nums, target) should return the index of the first value at least target in a sorted list (len(nums) if none), by binary search; count_between(nums, lo, hi) counts values in lo to hi inclusive using it. There are three bugs: the search moves hi = mid - 1, which can skip the answer; the loop runs while lo <= hi with that, which can run past the end; and count_between searches for hi instead of hi + 1, missing values equal to hi. Fix them so this prints [3, 4, 3].

Exercise20 points
B8: Stretches with a given XOR

Write count_xor_stretches(nums, k): how many non-empty stretches of neighbouring numbers have XOR equal to k, and longest_xor_stretch(nums, k): the length of the longest such stretch (0 if none), both in O(n) with prefix XORs and a dict (the XOR of nums[i:j] is prefix[j] ^ prefix[i]).

Part C: a larger program

Exercise50 points
C: An order book

A small exchange matches orders to buy and sell one share at a time. Write a class OrderBook():

  • buy(trader, price, quantity) and sell(trader, price, quantity) each place an order and return its id (1, 2, 3, … across both kinds). Raise ValueError for a price or quantity that isn’t a positive whole number.
  • Matching: a new buy order trades with resting sell orders whose price is at most its price, best (lowest) price first, and among equal prices the oldest first; a new sell order trades with resting buys at at least its price, highest first, oldest first. Each trade happens at the resting order’s price. Whatever quantity is left rests in the book. Use two heaps.
  • trades(): every trade so far, in order, as (buyer, seller, price, quantity).
  • cancel(order_id): remove a resting order (use lazy deletion: mark it cancelled and skip it when it reaches the top of a heap); KeyError if the id isn’t resting.
  • best_bid() and best_ask(): the highest resting buy price and lowest resting sell price, or None.
  • depth(side, levels): for "buy" or "sell", a list of (price, total quantity) for the best levels price levels, best first.

When you finish

Add up your marks: 1 for each quiz question right first time, and the full marks for each problem whose checks all pass. Write your total down, with the time you took and a note of every problem you didn’t finish or found hard. Don’t look anything up: tomorrow’s debrief goes through everything, with a second chance at each skill.
