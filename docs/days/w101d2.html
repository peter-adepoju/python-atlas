Week 101, Day 2

Record an explanation

Some ideas are best explained aloud, with a voice and a screen: a five-minute video on why backup = route doesn’t copy a list will help more beginners than a page of rules. Good explanations share a shape: they start with a prediction that the learner will probably get wrong, show what really happens, name the idea, and check understanding with another question, which is how every day of this course has worked. Today you’ll design explanations from the misconceptions learners actually have, generate prediction questions from code, order the ideas, and check a script before recording it.

By the end of today you can

  • Build an explanation around a prediction and a common misconception
  • Turn learners’ wrong answers into a ranked list of misconceptions
  • Generate prediction questions with plausible wrong options
  • Order ideas so each builds on what’s been explained
  • Check a script’s questions, length and terms before recording

Today we're going to look at what happens when you copy a list.

Say we have a list of places called route, and we write backup = route. Then we append Ridge to route. What do you think backup holds now?

Most people expect the old list. In fact both names refer to the same list object, so the append shows up through both names. Assignment never copies in Python: it gives an object another name. That's called aliasing.

Python keeps one object and a count of how many names refer to it. When you want a separate list, ask for one: backup = route.copy(), or list(route), or route[:]. Each makes a new outer list. A shallow copy still shares the objects inside it, which matters for a list of lists, and for that you use copy.deepcopy. The same is true for dictionaries and sets, and for any object you pass to a function, because passing an argument is assignment too, so a function that appends to a list you gave it changes your list. This is also why default arguments that are lists are shared between calls, which we saw in an earlier week, and why tuples, which can't change, never surprise you in this way.

So here's a question to check. If grid is a list of two lists and copy is grid.copy(), and we set grid[0][0] to 9, what's copy[0][0]?

It's 9, because the inner lists are shared. Try it yourself, then try copy.deepcopy.

Warm-up

If you predicted ['Mill', 'Weir'], you have the most common Python misconception, and you’ll never forget the correction now that you’ve been surprised by it. That’s the whole method: a surprise first, then the explanation. script.txt is a draft video script on exactly this.

Predict, observe, explain

The sequence this course uses daily has a long history in teaching (often called predict, observe, explain): ask the learner to commit to a prediction, show what really happens, then explain the gap. Committing makes the learner care about the answer, and the surprise marks the memory. Then check: a second, slightly different question shows whether the idea transferred. A good five-minute explanation might be: a question (30 seconds), the reveal (30), the idea named and shown two ways (2 minutes), a check question (1 minute), and a summary (30).

Misconceptions

Beginners don’t arrive empty: they bring models of how things work, some wrong in predictable ways. “Assignment copies”, “a function can’t change my variable”, “0.1 + 0.2 == 0.3”. The best explanations are built on them: collect learners’ actual wrong answers (from quizzes, questions, forums), count them, and aim the explanation at the most common. The same wrong models give you plausible wrong options for a prediction question, which is far better than random ones: each wrong option diagnoses a particular misunderstanding.

Recording

Use what Week 92 taught: a script timed at about 150 words a minute, large text on screen, captions, and chapters. Keep it to one idea: two ideas make two videos. Pause on screen after each question (“pause the video and decide”) and say the answer only after. Free tools such as OBS Studio record the screen; your voice matters more than your camera.

Key idea

Explain with predict, observe, explain, then check with a second question. Build explanations on the misconceptions learners actually have: count real wrong answers and aim at the most common. Use wrong models to write plausible wrong options. Order ideas so each depends only on what came before. One idea per video, scripted and timed, with pauses after questions.

Your explanation

  1. Pick one idea a beginner gets wrong (from your own early mistakes, or a quiz question in this course that caught you).
  2. Collect wrong answers: ask three or four people to predict, and note what they say.
  3. Write the script around a prediction, the reveal, the idea, a check question and a summary; run script_check on it.
  4. Record it in under six minutes with captions, and watch it once with the sound off.
