Week 89, Day 2

Build

Week 87’s spike found that searching every loop for a round walk explodes on a real map: the number of simple loops grows exponentially with its size. Today you’ll build S4, round walks, the way the spike’s ADR decided: go out to a turning point by the shortest route, and come back by the shortest route that doesn’t reuse the paths you went out on. The work becomes one search from the start (to find every junction’s distance), plus two short searches per candidate turning point, which a laptop does in milliseconds on thousands of junctions. You’ll build single-source shortest paths, route reconstruction, search with banned paths, loops through a turning point, and the choice of candidates, then put them together in the challenge.

By the end of today you can

  • Compute shortest distances from one junction to all others, and rebuild routes from them
  • Search while avoiding some paths, without changing the network
  • Build a round walk through a turning point that doesn’t retrace its steps
  • Choose candidate turning points from a target time, and deduplicate results
  • Replace an exponential search with a polynomial one that’s good enough

waymark_domain.py
import heapq


class UnknownPlace(LookupError):
    pass


class NoRoute(Exception):
    pass


def naismith_minutes(km, climb_m):
    return round(km / 5 * 60 + climb_m / 600 * 60)


class Route:
    def __init__(self, stops, km, climb_m):
        self.stops, self.km, self.climb_m = list(stops), km, climb_m

    @property
    def minutes(self):
        return naismith_minutes(self.km, self.climb_m)

    def __repr__(self):
        return f"Route({self.stops}, {self.km} km, {self.climb_m} m)"


class PathNetwork:
    def __init__(self, heights):
        self.heights = dict(heights)
        self.paths = {name: {} for name in self.heights}

    def _check(self, *names):
        for name in names:
            if name not in self.heights:
                raise UnknownPlace(name)

    def add_path(self, a, b, km):
        self._check(a, b)
        if km <= 0:
            raise ValueError("km must be positive")
        self.paths[a][b] = km
        self.paths[b][a] = km

    def climb(self, stops):
        return sum(max(0, self.heights[b] - self.heights[a]) for a, b in zip(stops, stops[1:]))

    def shortest(self, start, end):
        self._check(start, end)
        dist, prev, done = {start: 0}, {}, set()
        heap = [(0, start)]
        while heap:
            d, node = heapq.heappop(heap)
            if node in done:
                continue
            done.add(node)
            if node == end:
                break
            for nxt, km in sorted(self.paths[node].items()):
                if d + km < dist.get(nxt, float("inf")):
                    dist[nxt] = d + km
                    prev[nxt] = node
                    heapq.heappush(heap, (d + km, nxt))
        if end not in done:
            raise NoRoute(f"no route from {start} to {end}")
        stops = [end]
        while stops[-1] != start:
            stops.append(prev[stops[-1]])
        stops.reverse()
        return Route(stops, round(dist[end], 2), self.climb(stops))

waymark_geo.py
import math
from waymark_domain import PathNetwork
from waymark_map import HEIGHTS, PATHS

POSITIONS = {"Mill": (0.0, 0.0), "Weir": (1.4, 0.4), "Church": (2.8, 1.2), "Ridge": (4.4, 3.4), "Farm": (2.8, 2.4),
             "Wood": (2.0, 3.5), "Lake": (0.6, 2.8), "Island": (-3.0, 5.0)}


class GeoNetwork(PathNetwork):
    """A path network whose junctions also have positions, in kilometres east and north."""

    def __init__(self, heights, positions):
        super().__init__(heights)
        self.positions = dict(positions)

    def straight_km(self, a, b):
        return math.dist(self.positions[a], self.positions[b])


def sample_geo():
    network = GeoNetwork(HEIGHTS, POSITIONS)
    for a, b, km in PATHS:
        network.add_path(a, b, km)
    return network


def grid_network(size):
    """A size-by-size grid of junctions named 'r-c', 1 km apart, with slightly longer paths to their neighbours."""
    names = {(r, c): f"{r}-{c}" for r in range(size) for c in range(size)}
    heights = {name: ((r * 13 + c * 7) % 9) * 20 for (r, c), name in names.items()}
    positions = {name: (float(c), float(r)) for (r, c), name in names.items()}
    network = GeoNetwork(heights, positions)
    for (r, c), name in names.items():
        if c + 1 < size:
            network.add_path(name, names[(r, c + 1)], 1.0 + ((r * 7 + c * 3) % 5) / 10)
        if r + 1 < size:
            network.add_path(name, names[(r + 1, c)], 1.0 + ((r * 3 + c * 5) % 5) / 10)
    return network

Warm-up

Each extra junction allowed multiplies the number of loops (each one counted in both directions). On a map of thousands of junctions, a walk of two hours passes through dozens of them: no computer can try them all. A different approach is needed, not a faster computer.

Why the spike failed

Week 87’s challenge found every loop and kept the ones near the target time. That’s exact, and exponential: the work doubles and redoubles with every junction a walk can pass through. The ADR chose a different idea, common in route planners: a round walk is an outward route to a turning point and a return route home. Pick the turning point well (about half the target distance away), take the shortest route there, and the shortest route back that avoids the outward paths. It won’t find every possible loop, but it finds good ones, fast, and the work grows only with the number of candidate turning points.

Distances to everywhere

Dijkstra’s algorithm doesn’t have to stop at one destination: run it until the heap is empty and it gives the shortest distance from the start to every reachable junction, plus, for each, the junction before it on that shortest route (prev). That’s the shortest-path tree from the start. One run answers “how far is every junction?” (to choose turning points) and “what’s the route to any of them?” (follow prev back from the junction to the start, then reverse).

Out and back a different way

The return route must not walk back along the outward paths, or the “round” walk is a there-and-back. Search for it with those paths banned: the same Dijkstra, skipping any step along a banned path (in either direction, since a path walked back is the same path). Pass the banned paths in as a set of frozenset({a, b}) pairs, rather than deleting them from the network: the network is shared (cached, even) and must not change.

If there’s no way back without retracing (the turning point is at the end of a dead-end path), that turning point gives no round walk: skip it.

Choosing turning points

A target of 2 hours is about 10 km on the flat (Naismith: 12 minutes per km), so a loop’s outward half is roughly 5 km. Candidate turning points are junctions whose shortest distance from the start is between about 30% and 60% of the target distance (the return route is usually longer than the outward one, because it avoids the obvious paths). For each candidate, build the loop, compute its time with the climb, and keep those within the tolerance. Different turning points can produce the same loop (any junction on a loop is its own turning point), so deduplicate by the set of paths used.

Key idea

Exhaustive searches that grow exponentially need a different idea, not a faster machine. Dijkstra run to completion gives distances and a shortest-path tree from one start to everywhere; follow prev back to rebuild any route. Search while avoiding paths by skipping banned pairs (both directions), never by changing a shared network. A round walk is out to a turning point and back by the shortest route avoiding the outward paths; choose turning points at 30% to 60% of the target distance, skip ones with no way back, keep loops within the time tolerance, and deduplicate by the set of paths used.

Bug hunt10 points
A route walked backwards

Following prev from the end gives the stops in reverse, and the code forgets to turn them round: it prints ['Ridge', 'Farm', 'Weir', 'Mill']. Reverse them, so it prints ['Mill', 'Weir', 'Farm', 'Ridge'].

Bug hunt10 points
Back the way we came

The banned set holds the outward steps as ordered pairs, so walking the same path the other way isn’t banned and the “round” walk retraces it: it prints True. Ban paths in both directions (use frozenset pairs), so it prints False.
