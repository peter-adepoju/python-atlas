How to use this

Treat the first two hours as the real thing: notes closed, no tutor, no web, timer on. Run your code and press Check as often as you like. Unlike Friday, each problem has a hint and a model solution: don’t open them until the timer has finished. Then go back through every problem and compare.

Part A: quiz

Quiz10 questions

Part B: five problems

Exercise10 points
P1: The nearest shops

Shops stand at points (x, y). Write nearest(shops, home, k): the k shops nearest to home by straight-line distance (compare squared distances: no square roots needed), nearest first, ties broken by the point itself. Use a heap of size k, so it’s O(n log k).

Exercise15 points
P2: Two teams

People 0 to n − 1 must be split into two teams so that every pair in rivals is in different teams. Write two_teams(n, rivals): a list of each person’s team (0 or 1), choosing team 0 for the lowest-numbered person of each group, or None if impossible. BFS colouring.

Exercise15 points
P3: Hidden copies

Write count_hidden(text, word): the number of ways to pick letters from text, in order (not necessarily neighbouring), that spell word: “rabbbit” contains “rabbit” 3 ways. A DP over prefixes of both strings, with one row.

Exercise15 points
P4: Fewest fuel stops

A car must drive target miles; it starts with fuel miles’ worth in the tank (the tank is big enough for anything). stations are (mile, fuel), sorted by mile. Write fewest_stops(target, fuel, stations): the fewest stops needed, or -1. Greedy with a heap: drive as far as you can; when you’d run out, refuel (retroactively) at the biggest station already passed.

Exercise15 points
P5: Subsets with a given XOR

Write xor_subsets(nums, x): how many subsets (including the empty one) of a list of numbers from 0 to 1023 have XOR equal to x, mod 10⁹ + 7. Up to 1,000 numbers: a DP over the 1024 possible XOR values, one number at a time.

Part C: a larger program

Exercise30 points
C: A metro planner

Write a class Metro() for planning journeys on a metro of lines and stations.

  • add_line(name, stations, minutes): a line runs through the stations in order, both ways; minutes[i] is the time between stations[i] and stations[i + 1]. ValueError if the lengths don’t fit (there must be one fewer time than stations) or the line name is already used.
  • lines_at(station): the sorted names of the lines through a station (KeyError if unknown).
  • fastest(a, b, change=5): (minutes, route) for the quickest journey, where changing lines at a station costs change minutes. The route is a list of (station, line) pairs, starting at a and ending at b. Dijkstra over states (station, line); starting on any line at a is free. None if unreachable; (0, [(a, None)]) if a is b. KeyError for unknown stations.
  • fewest_changes(a, b): the fewest line changes for any journey from a to b (0 on a single line), or None. BFS over lines (0-1 BFS or BFS on states also works).
  • within(a, limit, change=5): the sorted list of stations reachable from a in at most limit minutes.

Afterwards

When the timer ends, add up your marks, then go back through each problem with its hint and solution. For every mark you dropped, write one line: the problem, the reason (didn’t know it, misread it, an edge case, ran out of time) and the week to revise. Tomorrow’s weak-spot drills are organised by topic: you’ll start with the ones on your list.

Which patterns did today need? P1 a heap of size k (Week 47); P2 BFS two-colouring (Week 50); P3 a two-string counting DP with one row (Weeks 53 and 54); P4 greedy with a heap, retroactive choices (Week 52 and 47); P5 a DP over XOR values (Weeks 53 and 55); C Dijkstra over richer states and 0-1 BFS (Weeks 50 and 51).
