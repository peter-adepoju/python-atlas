## A review checklist

Before calling any project done, go through a list like this one. Answer each honestly for your own `spend`.

**Does it meet the brief?** Go back to Day 1's list of eight requirements and the rules for the data. Try each one. (Did you build all of them? Does `add` really report every problem at once?)

**Is it correct at the edges?** The empty data file, a month with nothing in it, an amount of exactly £0.01, 29 February, a note of exactly 60 characters, a budget spent to the penny.

**Is it safe?** Can any command lose data? What happens if the data file is damaged, or the disk is full during a save, or a statement file doesn't exist?

**Is it tested?** Is every module tested? Would the tests catch the bugs you'd most fear? Do they run in under a second, and pass every time?

**Is it clear?** Does each function do one job, with a name that says what? Does each module have a docstring, and each function that isn't obvious? Could someone new find where to change the rent rule in a minute?

**Is it usable?** Are error messages specific enough to fix the problem without reading the code? Does `--help` explain every command? Does the README get a new person started?

## The decisions that paid off

Several decisions on Day 1 made everything after them easier. They're worth recognising, because you'll make the same choices in other projects:

- **Whole pence.** Not a single rounding bug all week. Compare the first code review below.
- **Check at the edge.** Everything is checked once, as it arrives (typed, or from a file), so the core never has to wonder whether an amount is valid.
- **Pure core, thin shell.** Only `spend.py` prints or reads arguments, so the core and storage were tested with plain function calls, and the interface needed only a handful of end-to-end tests.
- **Pass in the outside world.** `today`, `environ` and `argv` are parameters, so tests could choose any date, environment and command line.
- **All or nothing.** `add_expense` checks everything before changing anything; `save_data` replaces the file only when the new one is complete. A failure never leaves half a change behind.
- **Tests before change.** Day 2's tests made Day 5's refactor a ten-minute job instead of a risk.

=== money.py
"""Reading and showing money and categories."""
import re

AMOUNT = re.compile(r"£?\s*(\d{1,3}(?:,\d{3})+|\d+)(?:\.(\d{1,2}))?")


def parse_amount(text):
    """Text such as '£1,250.50' as whole pence. Raises ValueError with a readable message."""
    text = text.strip()
    if not text.lstrip("£").strip():
        raise ValueError("missing amount")
    m = AMOUNT.fullmatch(text)
    if m is None:
        raise ValueError(f"not an amount: {text!r}")
    total = int(m.group(1).replace(",", "")) * 100 + int((m.group(2) or "").ljust(2, "0"))
    if total == 0:
        raise ValueError("amount must be more than £0")
    return total


def format_pence(pence):
    """1250 as '£12.50', -350 as '-£3.50'."""
    sign = "-" if pence < 0 else ""
    pounds, rest = divmod(abs(pence), 100)
    return f"{sign}£{pounds:,}.{rest:02d}"


def clean_category(text):
    """' Eating   Out ' as 'eating out'. Raises ValueError if it isn't words of letters."""
    shown = text.strip()
    if not shown:
        raise ValueError("missing category")
    cleaned = " ".join(shown.lower().split())
    if len(cleaned) > 20 or not re.fullmatch(r"[a-z]+( [a-z]+)*", cleaned):
        raise ValueError(f"bad category: {shown!r}")
    return cleaned
=== dates.py
"""Reading dates and months that people type, and stepping through months."""
import re
from datetime import datetime, timedelta

FORMATS = ["%Y-%m-%d", "%d/%m/%Y"]


def parse_date(text, today):
    """'2026-11-02', '02/11/2026', 'today', 'yesterday' or '' as ISO text. No future dates."""
    shown = text.strip()
    word = shown.lower()
    if word in ("", "today"):
        when = today
    elif word == "yesterday":
        when = today - timedelta(days=1)
    else:
        when = None
        for fmt in FORMATS:
            try:
                when = datetime.strptime(word, fmt).date()
                break
            except ValueError:
                pass
        if when is None:
            raise ValueError(f"not a date: {shown!r}")
    if when > today:
        raise ValueError(f"date is in the future: {when.isoformat()}")
    return when.isoformat()


def parse_month(text):
    """'2026-11' or '11/2026' as '2026-11'. Raises ValueError otherwise."""
    shown = text.strip()
    m = re.fullmatch(r"(\d{4})-(\d{2})", shown)
    if m:
        year, month = int(m.group(1)), int(m.group(2))
    else:
        m = re.fullmatch(r"(\d{1,2})/(\d{4})", shown)
        if not m:
            raise ValueError(f"not a month: {shown!r}")
        month, year = int(m.group(1)), int(m.group(2))
    if not 1 <= month <= 12:
        raise ValueError(f"not a month: {shown!r}")
    return f"{year}-{month:02d}"


def next_month(month):
    """'2026-12' gives '2027-01'."""
    year, m = int(month[:4]), int(month[5:])
    if m == 12:
        return f"{year + 1}-01"
    return f"{year}-{m + 1:02d}"
=== core.py
"""The expense tracker's data and the operations on it."""
from money import parse_amount, clean_category
from dates import parse_date, next_month


def new_data():
    return {"expenses": [], "budgets": {}, "next_id": 1}


def add_expense(data, amount_text, category_text, note, date_text, today):
    """Check every field, then add the expense, or raise one ValueError listing every problem."""
    problems = []
    amount = category = when = None
    try:
        amount = parse_amount(amount_text)
    except ValueError as e:
        problems.append(str(e))
    try:
        category = clean_category(category_text)
    except ValueError as e:
        problems.append(str(e))
    try:
        when = parse_date(date_text, today)
    except ValueError as e:
        problems.append(str(e))
    note = note.strip()
    if len(note) > 60:
        problems.append("note is longer than 60 characters")
    if problems:
        raise ValueError("; ".join(problems))
    expense = {"id": data["next_id"], "date": when, "amount": amount, "category": category, "note": note}
    data["expenses"].append(expense)
    data["next_id"] += 1
    return expense


def remove_expense(data, expense_id):
    """Remove and return the expense with this id. KeyError if there isn't one."""
    for i, e in enumerate(data["expenses"]):
        if e["id"] == expense_id:
            return data["expenses"].pop(i)
    raise KeyError(f"no expense #{expense_id}")


def filter_expenses(data, month=None, category=None):
    """A new list of the matching expenses, newest first (by date, then id)."""
    chosen = [e for e in data["expenses"]
              if (month is None or e["date"][:7] == month)
              and (category is None or e["category"] == category)]
    return sorted(chosen, key=lambda e: (e["date"], e["id"]), reverse=True)


def total(expenses):
    return sum(e["amount"] for e in expenses)


def by_category(expenses):
    """(category, pence) pairs, largest first, alphabetical for ties."""
    totals = {}
    for e in expenses:
        totals[e["category"]] = totals.get(e["category"], 0) + e["amount"]
    return sorted(totals.items(), key=lambda pair: (-pair[1], pair[0]))


def month_summary(data, month):
    """Count, total, a row per category with spending or a budget, and the categories over budget."""
    expenses = filter_expenses(data, month=month)
    spent = dict(by_category(expenses))
    rows = []
    for category in set(spent) | set(data["budgets"]):
        budget = data["budgets"].get(category)
        used = spent.get(category, 0)
        rows.append({"category": category, "spent": used, "budget": budget,
                     "left": None if budget is None else budget - used})
    rows.sort(key=lambda r: (-r["spent"], r["category"]))
    return {"month": month, "count": len(expenses), "total": total(expenses), "rows": rows,
            "over": [r["category"] for r in rows if r["left"] is not None and r["left"] < 0]}


def monthly_totals(data):
    """(month, pence) for every month from the first with spending to the last, gaps as 0."""
    totals = {}
    for e in data["expenses"]:
        totals[e["date"][:7]] = totals.get(e["date"][:7], 0) + e["amount"]
    if not totals:
        return []
    out = []
    month, last = min(totals), max(totals)
    while month <= last:
        out.append((month, totals.get(month, 0)))
        month = next_month(month)
    return out


def set_budget(data, category_text, amount_text):
    """Check both, then set the category's monthly budget. Returns (category, pence)."""
    problems = []
    category = amount = None
    try:
        category = clean_category(category_text)
    except ValueError as e:
        problems.append(str(e))
    try:
        amount = parse_amount(amount_text)
    except ValueError as e:
        problems.append(str(e))
    if problems:
        raise ValueError("; ".join(problems))
    data["budgets"][category] = amount
    return category, amount


def remove_budget(data, category_text):
    """Remove a category's budget and return it. KeyError if it has none."""
    category = clean_category(category_text)
    if category not in data["budgets"]:
        raise KeyError(f"no budget for {category!r}")
    return data["budgets"].pop(category)

## One more feature: forecasts

On 10 November, a budget summary says you've spent £30 of a £60 food budget. Sounds fine, but at that rate you'll spend £90 by the end of the month. A **forecast** projects spending to the month's end: spent so far ÷ days so far × days in the month. `calendar.monthrange(year, month)[1]` gives the number of days in a month (Week 20).

It fits the design without changing anything else: a pure function in the core, taking `today`, returning data for the interface to print.

@@solution
import calendar
from datetime import date

def forecast(data, today):
    month = today.isoformat()[:7]
    days = calendar.monthrange(today.year, today.month)[1]
    rows = []
    for category in sorted(data["budgets"]):
        budget = data["budgets"][category]
        spent = sum(e["amount"] for e in data["expenses"]
                    if e["category"] == category and e["date"][:7] == month and e["date"] <= today.isoformat())
        projected = spent * days // today.day
        if spent > budget:
            status = "over"
        elif projected > budget:
            status = "heading over"
        else:
            status = "on track"
        rows.append({"category": category, "budget": budget, "spent": spent,
                     "projected": projected, "status": status})
    return rows

## Where it could go next

Some directions, roughly in the order the course would equip you for them:

- **Recurring expenses**: rent on the 1st of every month, added automatically. A good exercise in dates and in not adding the same thing twice.
- **Objects** (Phase 3): an `Expense` class instead of a dictionary, with `amount` that can only be valid pence, and a `Ledger` that owns the list and the next id. You'll see how much of the checking moves into the classes.
- **A database** (later in the course): SQLite instead of a JSON file, once there are tens of thousands of expenses and you want to ask questions in SQL.
- **A web page or an app**: the core and storage wouldn't change at all. Only a new interface would be written, in place of `spend.py`. That's the strongest argument for the pure-core design.
