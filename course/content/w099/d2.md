## Warm-up

:::predict
base, cap = 1, 30
print([min(cap, base * 2 ** i) for i in range(7)])
:::

Doubling the wait after each failure (1, 2, 4, 8 seconds...) gives a struggling service room to recover; capping it stops the waits growing absurdly. Week 91 retried calls; a job queue retries whole jobs, and needs a little randomness too, so a thousand failed jobs don't all come back in the same second.

## What goes wrong

- **A worker crashes mid-job.** The queue must notice and give the job to another worker.
- **The same job runs twice.** Retries and crashes make duplicates unavoidable, so jobs must be **idempotent**: running twice has the same effect as once. Give each job an **idempotency key** and record finished keys.
- **A job always fails** (bad input). Retrying forever wastes workers; after a few attempts move it to a **dead-letter queue** for a person to inspect.
- **Arrivals outpace workers.** The backlog grows by the difference every second (Week 98's queues).
- **Low-priority jobs never run** while high-priority ones keep arriving: **starvation**. Raise a job's priority as it waits (**ageing**).

## Delivery guarantees

Most queues (Amazon SQS, RabbitMQ, Redis-based ones) give **at-least-once** delivery: a worker **receives** a job, which becomes invisible for a **visibility timeout**; if the worker **acknowledges** it in time, it's deleted; if not (a crash, or a job slower than the timeout), it reappears for another worker. That's why duplicates happen, and why the timeout must be longer than the slowest normal job. "Exactly once" is achieved, in practice, as at-least-once delivery plus idempotent handling.

## Sizing and fairness

Workers needed: Little's law again: busy workers = jobs a second × seconds a job; at 70% utilisation, divide by 0.7 and round up. Retries add load: if a fraction p of attempts fail, each job takes on average 1 + p + p² + ... attempts (up to the limit). Priority: a heap ordered by priority, then arrival; ageing subtracts from the priority number as time passes so old jobs eventually rise.

:::key
Retry jobs with capped exponential backoff plus jitter. Expect duplicates (at-least-once delivery): make handlers idempotent with keys. Visibility timeouts must exceed the slowest normal job; unacknowledged jobs reappear. After a few failed attempts, dead-letter the job. Size workers with Little's law at about 70%, counting retries. Age priorities to prevent starvation.
:::

:::exercise id=idempotent points=15 title="Harmless duplicates"
Write a class `Idempotent(handler, clock, keep_seconds)`: `run(key, payload)` calls `handler(payload)` the first time a key is seen and returns its result; a repeat of the key within `keep_seconds` (by `clock()`) returns the stored result without calling the handler. Keys older than `keep_seconds` are forgotten (and a later repeat runs again). `calls` counts handler calls.
@@starter

    ___
@@tests
def test_idempotent():
    "once, however many deliveries"
    now = [0]
    sent = []
    def send_email(payload):
        sent.append(payload)
        return f"sent to {payload}"
    job = Idempotent(send_email, lambda: now[0], keep_seconds=3600)
    assert job.run("k1", "ada@example.org") == "sent to ada@example.org"
    assert job.run("k1", "ada@example.org") == "sent to ada@example.org" and job.calls == 1
    job.run("k2", "bo@example.org")
    now[0] = 4000
    job.run("k1", "ada@example.org")
    assert job.calls == 3 and sent == ["ada@example.org", "bo@example.org", "ada@example.org"]
@@solution
class Idempotent:
    def __init__(self, handler, clock, keep_seconds):
        self.handler, self.clock, self.keep = handler, clock, keep_seconds
        self.done = {}
        self.calls = 0

    def run(self, key, payload):
        now = self.clock()
        self.done = {k: (t, r) for k, (t, r) in self.done.items() if now - t <= self.keep}
        if key in self.done:
            return self.done[key][1]
        self.calls += 1
        result = self.handler(payload)
        self.done[key] = (now, result)
        return result
:::

:::exercise id=visibility points=15 title="Timeouts and the dead-letter queue"
Write `deliveries(jobs, timeout, max_receives)`: each job is `(name, seconds, crashes)`: it takes `seconds` to process, and its first `crashes` attempts crash before acknowledging. An attempt succeeds if it doesn't crash and `seconds <= timeout`; otherwise the job reappears. Return `"NAME: delivered N, done"` or, once it has been received `max_receives` times without success, `"NAME: delivered N, dead-lettered"`.
@@starter
def deliveries(jobs, timeout, max_receives):
    ___
@@tests
def test_deliveries():
    "at least once"
    jobs = [("resize-1", 4, 0), ("resize-2", 4, 2), ("report", 90, 0), ("email", 1, 5)]
    assert deliveries(jobs, timeout=30, max_receives=4) == [
        "resize-1: delivered 1, done", "resize-2: delivered 3, done", "report: delivered 4, dead-lettered", "email: delivered 4, dead-lettered"]
    assert deliveries([("x", 30, 0)], 30, 1) == ["x: delivered 1, done"]
@@solution
def deliveries(jobs, timeout, max_receives):
    out = []
    for name, seconds, crashes in jobs:
        for attempt in range(1, max_receives + 1):
            if attempt > crashes and seconds <= timeout:
                out.append(f"{name}: delivered {attempt}, done")
                break
        else:
            out.append(f"{name}: delivered {max_receives}, dead-lettered")
    return out
:::

@@tests

    "Little's law, with retries"
    assert workers_needed(10, 2) == 29 and workers_needed(10, 2, utilisation=1) == 20

import math

def workers_needed(jobs_per_s, seconds_each, failure_rate=0.0, max_receives=1, utilisation=0.7):
    attempts = sum(failure_rate ** k for k in range(max_receives))
    busy = jobs_per_s * attempts * seconds_each
    return max(1, math.ceil(busy / utilisation - 1e-9))

    ___
@@tests
def test_order():
    "old jobs rise"
    jobs = [("stats", 5, 0), ("email", 1, 95), ("resize", 2, 90), ("backup", 5, 60)]
    assert run_order(jobs, now=100, ageing=20) == ["stats", "email", "resize", "backup"]

def run_order(jobs, now, ageing):
    key = lambda j: (j[1] - (now - j[2]) // ageing, j[2], j[0])
    return [name for name, _, _ in sorted(jobs, key=key)]

:::bughunt id=bug2 points=10 title="An email sent twice"
The handler never records which keys it has finished, so a redelivered job sends the email again and this prints `2`. Record finished keys and skip them so it prints `1`.
@@starter

    sent.append(address)

@@tests

    "idempotency keys"
    expect_output("1")
@@solution

done = set()

def handle(key, address):
    if key in done:
        return
    sent.append(address)
    done.add(key)

for key, address in [("k1", "ada@example.org"), ("k1", "ada@example.org")]:
    handle(key, address)
print(len(sent))

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: a queue plan"
Write `queue_plan(req)`. `req` has `jobs_per_s`, `seconds_each`, `failure_rate` (the chance an attempt fails), `max_receives`, `workers`, `timeout` and `slowest_seconds`. Return `(lines, warnings)`:

- `"attempts per job: A"` (`1 + p + ... + p^(m-1)`, 3 decimal places);
- `"dead-lettered: D%"` (`p^m` as a percentage, 3 decimal places);
- `"busy workers: B of W"` (jobs × attempts × seconds, 1 decimal place);
- `"utilisation: U%"` (busy over workers, 1 decimal place);
- `"backlog growth: G jobs a second"` (attempts arriving a second minus what the workers finish, `jobs × attempts − workers / seconds`, never below 0, 1 decimal place).

`warnings` lists, in this order, `"visibility timeout shorter than the slowest job"` if `timeout < slowest_seconds`, `"over 70% utilisation"` if it is, and `"queue grows without limit"` if the backlog growth is above 0.
@@starter
def queue_plan(req):
    ___
@@tests
REQ = {"jobs_per_s": 40, "seconds_each": 0.5, "failure_rate": 0.1, "max_receives": 4, "workers": 30, "timeout": 30, "slowest_seconds": 12}

def test_plan():
    "comfortable"
    lines, warnings = queue_plan(REQ)
    assert lines == ["attempts per job: 1.111", "dead-lettered: 0.010%", "busy workers: 22.2 of 30", "utilisation: 74.1%",
                     "backlog growth: 0.0 jobs a second"]
    assert warnings == ["over 70% utilisation"]

def test_trouble():
    "everything wrong"
    lines, warnings = queue_plan({**REQ, "workers": 20, "timeout": 10})
    assert lines[-1] == "backlog growth: 4.4 jobs a second"
    assert warnings == ["visibility timeout shorter than the slowest job", "over 70% utilisation", "queue grows without limit"]
    assert queue_plan({**REQ, "workers": 100})[1] == []
@@solution
def queue_plan(req):
    p, m = req["failure_rate"], req["max_receives"]
    attempts = sum(p ** k for k in range(m))
    busy = req["jobs_per_s"] * attempts * req["seconds_each"]
    utilisation = busy / req["workers"]
    growth = max(0.0, req["jobs_per_s"] * attempts - req["workers"] / req["seconds_each"])
    lines = [f"attempts per job: {attempts:.3f}", f"dead-lettered: {100 * p ** m:.3f}%",
             f"busy workers: {busy:.1f} of {req['workers']}", f"utilisation: {100 * utilisation:.1f}%",
             f"backlog growth: {growth:.1f} jobs a second"]
    warnings = []
    if req["timeout"] < req["slowest_seconds"]:
        warnings.append("visibility timeout shorter than the slowest job")
    if utilisation > 0.7:
        warnings.append("over 70% utilisation")
    if growth > 0:
        warnings.append("queue grows without limit")
    return lines, warnings
:::
