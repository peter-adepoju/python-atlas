## Warm-up

:::predict
multipliers = [lambda x: x * i for i in range(3)]
print([m(10) for m in multipliers])
:::

Every function uses the **same** `i`, looked up when it's called, after the loop has finished with `i == 2`. It's the most famous Python trap in interviews, and the reason today exists: the bug isn't where it looks.

## The method

1. **Read the error.** The last line of a traceback is the exception and its message; the frames above it go from the outermost call to the innermost, so the last `File` line is where it happened. Read the message literally: `KeyError: 'Ridge'` says which key.
2. **Reproduce** it with the smallest input you can (Week 95's minimising, or bisection over the input).
3. **Hypothesise** aloud: "I think `totals` is missing months with no walks".
4. **Test the hypothesis** with one experiment: a print, an assertion, a breakpoint (`breakpoint()` starts `pdb` on your own computer).
5. **Fix the cause**, not the symptom (a `try/except KeyError: pass` hides the bug).
6. **Add a test** that fails before the fix and passes after.

Say each step as you go; the interviewer is grading the method.

## Classic traps

- **Late-binding closures**: a function made in a loop sees the loop variable's final value. Bind it now with a default argument (`lambda x, i=i: x * i`).
- **Changing a list while looping over it**: removing items shifts the rest, so some are skipped. Build a new list instead.
- **Float equality**: `0.1 + 0.2 == 0.3` is `False`. Use `math.isclose`, or `Decimal` for money.
- **Numbers read as text**: input, CSV and JSON keys give strings, and `"9" > "10"` is `True`. Convert before comparing.
- **Shadowed built-ins**: `list = ...` or `sum = 0` replaces the built-in for the rest of the scope, and a later `list(...)` fails with `TypeError: 'list' object is not callable`.

:::key
Read the error (last line, innermost frame), reproduce small, hypothesise aloud, test with one experiment, fix the cause, add a test. Watch for late-binding closures (bind with a default argument), changing a list while iterating (build a new one), float equality (`isclose`, `Decimal`), numbers read as text (convert first), and shadowed built-ins.
:::

:::exercise id=traceback points=10 title="Reading a traceback"
Write `innermost(traceback_text)`: from a standard traceback, return a dict with `file`, `line` (an int) and `function` from the **last** `File "...", line N, in NAME` line, and `error` and `message` from the last line (split at the first `": "`; the message is `""` if there's none).
@@starter
import re

def innermost(traceback_text):
    ___
@@tests
TB = """Traceback (most recent call last):
  File "/home/ada/waymark/cli.py", line 41, in main
    report = monthly(walks)
  File "/home/ada/waymark/stats.py", line 17, in monthly
    totals[month] += walk["km"]
KeyError: '2026-02'"""

def test_innermost():
    "where it really happened"
    assert innermost(TB) == {"file": "/home/ada/waymark/stats.py", "line": 17, "function": "monthly",
                             "error": "KeyError", "message": "'2026-02'"}
    tb2 = 'Traceback (most recent call last):\n  File "<stdin>", line 1, in <module>\nStopIteration'
    assert innermost(tb2) == {"file": "<stdin>", "line": 1, "function": "<module>", "error": "StopIteration", "message": ""}
@@solution
import re

def innermost(traceback_text):
    frames = re.findall(r'File "([^"]+)", line (\d+), in (\S+)', traceback_text)
    file, line, function = frames[-1]
    last = traceback_text.strip().splitlines()[-1]
    error, _, message = last.partition(": ")
    return {"file": file, "line": int(line), "function": function, "error": error, "message": message}
:::

:::exercise id=narrow points=15 title="Narrowing the input"
A function fails on a long list of inputs, and once it fails on a prefix it fails on every longer prefix. Write `first_failing_prefix(items, fails)`: the smallest `n` such that `fails(items[:n])` is true, found by binary search, and the number of calls made, as `(n, calls)`; `(None, calls)` if even the whole list doesn't fail.
@@starter
def first_failing_prefix(items, fails):
    ___
@@tests
def test_narrow():
    "the walk that broke it"
    walks = [{"km": 5}] * 700 + [{"km": None}] + [{"km": 3}] * 299
    fails = lambda part: any(w["km"] is None for w in part)
    n, calls = first_failing_prefix(walks, fails)
    assert n == 701 and calls <= 11, (n, calls)
    assert first_failing_prefix([1, 2, 3], lambda p: False)[0] is None
    assert first_failing_prefix([0], lambda p: 0 in p) == (1, 1)
@@solution
def first_failing_prefix(items, fails):
    calls = 1
    if not fails(items):
        return None, calls
    lo, hi = 0, len(items)
    while hi - lo > 1:
        mid = (lo + hi) // 2
        calls += 1
        if fails(items[:mid]):
            hi = mid
        else:
            lo = mid
    return hi, calls
:::

:::exercise id=closures points=10 title="Functions made in a loop"
`make_multipliers(n)` should return `n` functions where the `i`-th multiplies by `i`, but every one multiplies by `n - 1`. Fix it.
@@starter
def make_multipliers(n):
    return [lambda x: x * i for i in range(n)]
@@tests
def test_closures():
    "bound now, not later"
    assert [m(10) for m in make_multipliers(3)] == [0, 10, 20] and make_multipliers(0) == []
@@solution
def make_multipliers(n):
    return [lambda x, i=i: x * i for i in range(n)]
:::

:::exercise id=mutating points=10 title="Removing while looping"
`remove_short(words, n)` should remove every word shorter than `n` and return the list, but removing while looping skips the word after each removal. Fix it so it returns a new list and leaves `words` unchanged.
@@starter
def remove_short(words, n):
    for w in words:
        if len(w) < n:
            words.remove(w)
    return words
@@tests
def test_remove():
    "nothing skipped"
    words = ["a", "be", "walk", "up", "hill", "to"]
    assert remove_short(words, 3) == ["walk", "hill"] and words == ["a", "be", "walk", "up", "hill", "to"]
@@solution
def remove_short(words, n):
    return [w for w in words if len(w) >= n]
:::

:::exercise id=floats points=10 title="Totals that didn't add up"
`matches_total(prices, total)` compares a sum of floats with `==`, so `[0.1, 0.2]` doesn't match `0.3`. Fix it to compare to within half a penny (`abs_tol=0.005`) with `math.isclose`.
@@starter
import math

def matches_total(prices, total):
    return sum(prices) == total
@@tests
def test_floats():
    "close enough, and no closer"
    assert matches_total([0.1, 0.2], 0.3) and matches_total([19.99, 5.01], 25.0)
    assert not matches_total([10.0, 2.0], 12.01) and matches_total([], 0)
@@solution
import math

def matches_total(prices, total):
    return math.isclose(sum(prices), total, abs_tol=0.005)
:::

## Daily challenge

:::exercise id=challenge points=25 title="Challenge: a tiny post-mortem debugger"
Write `post_mortem(source, call)`: compile `source` with the file name `"<debugged>"`, execute it into a namespace, then evaluate the expression `call` in that namespace. If it raises, return lines: `"ERROR: MESSAGE"` (the exception's class name and its `str`), `"at line N in FUNCTION: TEXT"` for the **innermost** frame from `"<debugged>"` (TEXT the stripped source line), and `"  NAME = VALUE"` for each local variable of that frame, sorted by name, VALUE written with `repr`. If it doesn't raise, return `["no error: RESULT"]` with the result's `repr`.
@@starter
import sys
import traceback

def post_mortem(source, call):
    ___
@@tests
SOURCE = '''def monthly(walks):
    totals = {}
    for walk in walks:
        month = walk["day"][:7]
        totals[month] += walk["km"]
    return totals

def report(walks):
    return monthly(walks)
'''

def test_error():
    "where, and with what"
    lines = post_mortem(SOURCE, 'report([{"day": "2026-02-01", "km": 6.0}])')
    assert lines == ["KeyError: '2026-02'", "at line 5 in monthly: totals[month] += walk[\"km\"]",
                     "  month = '2026-02'", "  totals = {}", "  walk = {'day': '2026-02-01', 'km': 6.0}",
                     "  walks = [{'day': '2026-02-01', 'km': 6.0}]"]

def test_fine():
    "no error"
    assert post_mortem(SOURCE, "report([])") == ["no error: {}"]
    assert post_mortem("def f(x):\n    return 1 / x\n", "f(0)")[:2] == ["ZeroDivisionError: division by zero", "at line 2 in f: return 1 / x"]
@@solution
import sys
import traceback

def post_mortem(source, call):
    namespace = {}
    exec(compile(source, "<debugged>", "exec"), namespace)
    try:
        result = eval(call, namespace)
    except Exception as exc:
        tb, frame = exc.__traceback__, None
        while tb is not None:
            if tb.tb_frame.f_code.co_filename == "<debugged>":
                frame, line = tb.tb_frame, tb.tb_lineno
            tb = tb.tb_next
        text = source.splitlines()[line - 1].strip()
        lines = [f"{type(exc).__name__}: {exc}", f"at line {line} in {frame.f_code.co_name}: {text}"]
        lines += [f"  {name} = {value!r}" for name, value in sorted(frame.f_locals.items())]
        return lines
    return [f"no error: {result!r}"]
:::
