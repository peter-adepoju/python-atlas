## Warm-up

:::predict
def pair_slow(nums, target):
    checks = 0
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            checks += 1
            if nums[i] + nums[j] == target:
                return (i, j), checks
    return None, checks

def pair_fast(nums, target):
    seen = {}                                  # value -> position
    for j, x in enumerate(nums):
        if target - x in seen:
            return (seen[target - x], j), j + 1
        seen[x] = j
    return None, len(nums)

nums = list(range(0, 4000, 2))
print(pair_slow(nums, 7994), pair_fast(nums, 7994))
:::

The same answer, after about two million checks or two thousand dictionary lookups. That's the whole of today in one example: replace an inner loop with a lookup.

## Have I seen its partner?

The **two-sum** pattern: for each item, ask whether its **partner** (the value that would complete the answer) has already appeared, by looking it up in a dictionary of the items seen so far. Then record the item itself. Checking **before** recording means an item can't pair with itself.

The same shape answers many questions: two numbers with a given sum or difference, a word and its reverse, a person and someone born on the same day, a transaction and its refund. The dictionary maps whatever you'll look up (the value) to whatever you need back (a position, a count, the item).

## Grouping by a canonical key

To group things that are "the same" in some sense, compute a **canonical key** (one standard form for everything in a group) and use it as a dictionary key:

| Group | Canonical key |
|---|---|
| anagrams | `"".join(sorted(word))`, or a tuple of 26 letter counts |
| words with the same letters, ignoring repeats | `frozenset(word)` |
| shifted strings (`"abc"`, `"bcd"`, `"xyz"`) | the differences between neighbouring letters, mod 26, as a tuple |
| files with the same contents | a hash of the contents (Day 1) |
| rotations of a shape | the smallest of its rotations |

:::example
def group_anagrams(words):
    groups = {}
    for w in words:
        groups.setdefault("".join(sorted(w)), []).append(w)
    return list(groups.values())

print(group_anagrams(["listen", "google", "silent", "elgoog", "enlist", "cat", "act", "tac", "dog"]))
:::

Sorting each word costs O(k log k) for a word of k letters, so grouping n words is O(n k log k): far better than comparing every pair of words.

## Counting

Counting is a dictionary from item to count (Week 14's frequency map); `collections.Counter` (Week 20) does it in one line and adds `most_common`. Counting answers questions like:

:::example
from collections import Counter

text = "the cat and the hat and the bat"
counts = Counter(text.split())
print(counts.most_common(2))
letters = Counter("swiss")
print(next((ch for ch in "swiss" if letters[ch] == 1), None))      # the first letter that appears once
print(Counter("listen") == Counter("silent"))                       # anagrams, by counting
:::

Comparing two `Counter`s is an O(n) anagram test, faster than sorting both.

## Sets for membership

A set answers "is this here?" in O(1). The classic problem: the **longest run of consecutive numbers** in an unsorted list (`[100, 4, 200, 1, 3, 2]` has `1 2 3 4`). Sorting would be O(n log n). With a set, start counting only from numbers that **begin** a run (whose predecessor isn't in the set), and walk upwards:

:::example
def longest_run(nums):
    have = set(nums)
    best = 0
    for x in have:
        if x - 1 not in have:                  # x starts a run
            length = 1
            while x + length in have:
                length += 1
            best = max(best, length)
    return best

print(longest_run([100, 4, 200, 1, 3, 2]), longest_run([0, 3, 7, 2, 5, 8, 4, 6, 0, 1]), longest_run([]))
:::

There's a loop inside a loop again, but each number is walked over at most once in total, because only run starts begin a walk: O(n), by the same amortised reasoning as Week 41's windows.

## Remembering where

A dictionary from value to its **last position** answers "how far back did I last see this?": duplicates within k positions, the longest gap between repeats, or (with the first position instead) the longest stretch between two equal values. Week 41's longest run without repeats used exactly this.

:::example
def repeats_within(nums, k):
    last = {}
    for i, x in enumerate(nums):
        if x in last and i - last[x] <= k:
            return True
        last[x] = i
    return False

print(repeats_within([1, 2, 3, 1], 3), repeats_within([1, 2, 3, 1], 2), repeats_within([1, 0, 1, 1], 1))
:::

## Making keys

Dictionary keys and set items must be hashable, and lists, sets and dicts aren't (Day 1). Convert them:

| You have | Use as a key |
|---|---|
| a list | `tuple(the_list)` |
| a set | `frozenset(the_set)` |
| a dict | `frozenset(the_dict.items())` (if its values are hashable) |
| a grid (list of lists) | `tuple(map(tuple, grid))` |
| a point or pair | a tuple, `(x, y)` |

:::example
seen_states = set()
board = [[1, 2], [3, 0]]
seen_states.add(tuple(map(tuple, board)))
print((tuple(map(tuple, [[1, 2], [3, 0]])) in seen_states), frozenset("abc") == frozenset("cba"))
:::

:::key
Many O(n²) "every pair" problems become O(n) with one pass and a dictionary or set. Look up each item's partner among those already seen, then record the item (in that order). Group by a canonical key, such as sorted letters. Count with a dictionary or `Counter`. Use a set for membership: the longest consecutive run starts only from numbers whose predecessor is missing. Remember last positions to answer "how far back?". Turn unhashable values into keys with `tuple`, `frozenset` and `tuple(map(tuple, grid))`.

def longest_consecutive(nums):
    have = set(nums)
    best_start, best_len = None, 0
    for x in have:
        if x - 1 not in have:
            length = 1
            while x + length in have:
                length += 1
            if length > best_len or (length == best_len and x < best_start):
                best_start, best_len = x, length
    return [] if best_start is None else list(range(best_start, best_start + best_len))

For each point `p`, make a dictionary `directions`. For every other point `q`: if it's equal to `p`, add 1 to `same`; otherwise work out `dx, dy`, divide both by `g = gcd(dx, dy)`, flip both signs if `dx < 0` or (`dx == 0` and `dy < 0`), and count that key. The best for `p` is `same + 1 + max(directions.values(), default=0)`.
@@solution
from math import gcd

def most_on_a_line(points):
    best = 0
    for i, (x1, y1) in enumerate(points):
        directions = {}
        same = 0
        for j, (x2, y2) in enumerate(points):
            if i == j:
                continue
            dx, dy = x2 - x1, y2 - y1
            if dx == 0 and dy == 0:
                same += 1
                continue
            g = gcd(dx, dy)
            dx, dy = dx // g, dy // g
            if dx < 0 or (dx == 0 and dy < 0):
                dx, dy = -dx, -dy
            directions[(dy, dx)] = directions.get((dy, dx), 0) + 1
        best = max(best, same + 1 + max(directions.values(), default=0))
    return best
