## Warm-up

:::predict
class Book:
    loan_days = 21

    def __init__(self, title):
        self.title = title

    def label(self):
        return f"{self.title} ({self.loan_days} days)"

class Ebook(Book):
    pass

e = Ebook("Half of a Yellow Sun")
print(e.label())
print(isinstance(e, Ebook), isinstance(e, Book), type(e) == Book)
:::

`Ebook` has an empty body, yet its objects have an `__init__`, a `label` method and a `loan_days`: all of them come from `Book`. An ebook also counts as a `Book` for `isinstance`, though its exact type is `Ebook`. That's inheritance, and today is about how it works and when it helps.

## One class built on another

Writing a class name in brackets after a new class makes the new class **inherit** from it:

```python
class Ebook(Book):
    ...
```

Everything `Book` defines (methods, class attributes, special methods like `__init__` and `__repr__`) is available to `Ebook` objects, without copying a line. You'll meet three pairs of words for the two classes; they mean the same thing:

| `Book` | `Ebook` |
|---|---|
| parent class | child class |
| base class | derived class |
| superclass | subclass |

The child then **adds** what's new and **replaces** what's different:

:::example
class Book:
    loan_days = 21

    def __init__(self, title, author):
        self.title = title
        self.author = author

    def label(self):
        return f"{self.title} by {self.author}, {self.loan_days}-day loan"

    def due(self, day):
        return day + self.loan_days

class Ebook(Book):
    loan_days = 14                       # replaces the parent's value

    def file_name(self):                 # new: only ebooks have this
        return self.title.lower().replace(" ", "_") + ".epub"

b = Book("Things Fall Apart", "Chinua Achebe")
e = Ebook("Small Island", "Andrea Levy")
print(b.label())
print(e.label())
print(e.file_name(), e.due(100), b.due(100))
try:
    b.file_name()
except AttributeError as err:
    print("AttributeError:", err)
:::

- `Ebook` inherits `__init__`, so `Ebook("Small Island", "Andrea Levy")` works exactly like making a `Book`.
- `label` and `due` are written once, in `Book`. When they run for an ebook, `self` **is** the ebook, so `self.loan_days` finds the ebook's 14. A parent's method automatically uses whatever the child changed.
- `file_name` exists only for ebooks. The parent knows nothing about its children: a plain `Book` has no `file_name`.

A child can also replace a **method** by defining one with the same name. That's called **overriding**, and Day 3 looks at it closely:

:::example
class Book:
    loan_days = 21

    def __init__(self, title, author):
        self.title = title
        self.author = author

    def label(self):
        return f"{self.title} by {self.author}, {self.loan_days}-day loan"

class ReferenceBook(Book):
    def label(self):
        return f"{self.title} by {self.author}, library use only"

for item in [Book("Aké", "Wole Soyinka"), ReferenceBook("The Atlas of Nigeria", "Various")]:
    print(item.label())
:::

Use inheritance when the sentence "every child **is a** parent" is true: every ebook is a book, every reference book is a book. If the sentence sounds wrong ("every library is a book"), inheritance is the wrong tool. Day 5 is about the alternative.

One thing catches everyone out. If the child writes its **own** `__init__`, it replaces the parent's completely, and the parent's `__init__` never runs:

:::example error=yes
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def label(self):
        return f"{self.title} by {self.author}"

class AudioBook(Book):
    def __init__(self, title, author, minutes):
        self.minutes = minutes            # title and author are never set

a = AudioBook("Girl, Woman, Other", "Bernardine Evaristo", 700)
print(a.minutes)
print(a.label())
:::

You could copy the parent's lines into the child, but then the same code lives in two places. Tomorrow's topic, `super()`, lets the child's `__init__` run the parent's and then add its own part. Today, children either keep the parent's `__init__` or set every attribute themselves.

## Finding attributes through the family

Week 28, Day 5 gave the rule for reading `obj.name`: look in the instance, then in its class. It left a gap for this week. Here's the full rule:

1. the instance's own attributes;
2. its class;
3. that class's parent, then the parent's parent, and so on up the family;
4. `AttributeError` if it's nowhere.

The first place that has the name wins, so a child's value hides its parent's, and an instance's own value hides both:

:::predict
class A:
    x = "A"
    y = "A"
    z = "A"

class B(A):
    y = "B"
    z = "B"

class C(B):
    z = "C"

c = C()
print(c.x, c.y, c.z)
c.z = "mine"
print(c.z, C.z, B.z)
A.x = "changed"
print(c.x)
:::

The search happens every time the attribute is read, so a change to `A.x` shows up at once in every child that doesn't have its own `x`.

At the very top of every family is `object`. A class with no brackets inherits from `object` anyway, which is where the default `__repr__` (`<__main__.Book object at 0x...>`), the identity-based `__eq__` and `__hash__`, and many other behaviours come from. Python keeps the search order of each class in its `__mro__` attribute (the "method resolution order", properly explained on Day 3):

:::example
class Item:
    pass

class Book(Item):
    pass

class Ebook(Book):
    pass

print([cls.__name__ for cls in Ebook.__mro__])
print(Ebook.__bases__, Item.__bases__)
print("__repr__" in vars(Item), "__repr__" in vars(object))
:::

`__bases__` holds a class's direct parents. `vars(Item)` shows only what `Item` itself defines, so `__repr__` isn't there; Python finds it in `object`.

## isinstance, issubclass and type

Because every ebook is a book, `isinstance(e, Book)` is True for an ebook. `isinstance` asks "is this object one of these, **or of any class built on it**?" Its partner `issubclass` asks the same question about two classes:

:::example
class Item:
    pass

class Book(Item):
    pass

class Ebook(Book):
    pass

class Dvd(Item):
    pass

e = Ebook()
print(isinstance(e, Ebook), isinstance(e, Book), isinstance(e, Item), isinstance(e, Dvd))
print(isinstance(e, (Dvd, Book)))
print(issubclass(Ebook, Item), issubclass(Item, Ebook), issubclass(Book, Book))
print(type(e) == Book, type(e).__name__)
:::

- `isinstance(x, (A, B))` with a tuple is True if `x` is either.
- A class counts as a subclass of itself, so `issubclass(Book, Book)` is True.
- `type(x) == Book` is True **only** for exact `Book` objects. Code that checks the type that way turns away ebooks, which is almost never what you want. Prefer `isinstance`, so that children are welcome wherever their parent is.

When an `if` chain sorts objects with `isinstance`, test the **most specific** class first. An ebook passes `isinstance(e, Item)`, so a chain that checks `Item` first never reaches `Book` or `Ebook`. You'll fix exactly that bug in the practice.

Now Week 28's promise. `bool` is a subclass of `int`: `True` and `False` are whole numbers with special names and a special repr.

:::predict
print(issubclass(bool, int), isinstance(True, int), type(True) == int)
print(True + True, sum([True, False, True, True]), True * 10)
:::

That's why `sum(mark >= 50 for mark in marks)` counts passes: each comparison gives a `bool`, and bools add up like 1s and 0s. It has a catch for validation, though. `isinstance(x, int)` accepts `True`, so if a function wants a real whole number (an age, a quantity), it must reject booleans explicitly:

:::example
def is_quantity(x):
    return isinstance(x, int) and not isinstance(x, bool) and x > 0

print([is_quantity(v) for v in [3, 0, True, 2.0, "3"]])
:::

## Writing for subclasses

In Weeks 28 and 29 you wrote `type(self).__name__` in reprs and `cls(...)` in class methods, "so subclasses work". Here's the payoff. First, with the class name written in by hand:

:::predict
class Book:
    loan_days = 21

    def __init__(self, title):
        self.title = title

    @classmethod
    def from_line(cls, line):
        return Book(line.strip())

    def __repr__(self):
        return f"Book({self.title!r})"

class Ebook(Book):
    loan_days = 14

e = Ebook.from_line("  Purple Hibiscus ")
print(e, e.loan_days, type(e).__name__)
:::

`Ebook.from_line` ran the inherited method, which made a **`Book`**, and the repr would have said `Book` even for a real ebook. The fix is to write neither name:

:::example
class Book:
    loan_days = 21

    def __init__(self, title):
        self.title = title

    @classmethod
    def from_line(cls, line):
        return cls(line.strip())              # cls is whichever class it was called on

    def __repr__(self):
        return f"{type(self).__name__}({self.title!r})"

class Ebook(Book):
    loan_days = 14

e = Ebook.from_line("  Purple Hibiscus ")
print(e, e.loan_days)
print(Book.from_line("Aké"))
:::

The same goes for any method that makes a new object of "the same kind", such as `__add__` from Week 29: `return type(self)(...)` makes one of the same class as `self`, while `return Money(...)` always makes the parent.

## A family of exceptions

You've been using inheritance since Week 11 without knowing it: exceptions are classes, arranged in families.

:::example
for cls in [ZeroDivisionError, ValueError, KeyError, IndexError, FileNotFoundError]:
    parents = [c.__name__ for c in cls.__mro__[1:]]
    print(cls.__name__, "->", " -> ".join(parents))
:::

`except` uses the same "is a" rule as `isinstance`: `except LookupError` catches both `KeyError` and `IndexError`, because both are lookup errors, and `except Exception` catches nearly everything (which is why it's usually too broad).

For your own programs, define exceptions by inheriting from `Exception`. A class body needs no more than a docstring:

:::example
class LibraryError(Exception):
    """Something went wrong in the library."""

class NotOnShelf(LibraryError):
    """The book exists but is out on loan."""

class LimitReached(LibraryError):
    """The member already has the most loans allowed."""

def borrow(loans, title, on_shelf, limit=3):
    if len(loans) >= limit:
        raise LimitReached(f"already {len(loans)} loans")
    if title not in on_shelf:
        raise NotOnShelf(f"{title!r} is out")
    on_shelf.remove(title)
    loans.append(title)

shelf = ["Aké", "Small Island", "Purple Hibiscus"]
mine = []
for title in ["Aké", "Aké", "Small Island", "Purple Hibiscus", "Things Fall Apart"]:
    try:
        borrow(mine, title, shelf)
        print("borrowed", title)
    except NotOnShelf as err:
        print("sorry:", err)
    except LibraryError as err:
        print(type(err).__name__, err)
print(mine)
:::

- The message you pass when raising comes back from `str(err)`, as with Python's own exceptions.
- Callers can catch one kind precisely (`except NotOnShelf`) or the whole family (`except LibraryError`), and errors from elsewhere still go past.
- Python tries `except` clauses in order and uses the first that matches, so put the specific ones first. With `except LibraryError` first, the `NotOnShelf` clause would never run.

If your error really is a kind of bad value, inherit from `ValueError` instead (`class BadISBN(ValueError): ...`). Then code that already catches `ValueError` keeps working, and code that wants only your error can catch it by name.

:::key
`class Child(Parent):` gives the child everything the parent defines; the child adds new methods and replaces anything it defines again, and the parent's methods, running with `self` as the child, use the child's values. Attribute lookup goes instance, class, parents up to `object`, and the first match wins. `isinstance` and `issubclass` accept subclasses (so `isinstance(True, int)` is True), which makes them better than `type(x) == ...`; check the most specific class first. Write `cls(...)` and `type(self)` instead of the class's name so subclasses get their own class back. Your own exceptions inherit from `Exception` (or `ValueError`), so callers can catch each one or the whole family.
:::

import math

class Shape:
    def area(self):
        raise NotImplementedError(f"{type(self).__name__} must define area()")

    def describe(self):
        return f"{type(self).__name__} with area {self.area():.2f}"

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return math.pi * self.radius ** 2

class Square(Rectangle):
    def __init__(self, side):
        self.width = side
        self.height = side

def largest(shapes):
    if not shapes:
        return None
    return max(shapes, key=lambda s: s.area())

class StockError(Exception):
    """A problem with the stock."""

class UnknownItem(StockError):
    """The item isn't stocked at all."""

class NotEnoughStock(StockError):
    """There aren't enough of the item."""

def take(stock, item, qty):
    if qty < 1:
        raise ValueError(f"qty must be at least 1, not {qty}")
    if item not in stock:
        raise UnknownItem(item)
    if stock[item] < qty:
        raise NotEnoughStock(f"only {stock[item]} {item} left")
    stock[item] -= qty
    return stock[item]

@@solution
class Item:
    VAT_RATE = 20

    def __init__(self, name, pence):
        if not isinstance(pence, int) or isinstance(pence, bool) or pence < 0:
            raise ValueError(f"price must be a whole number of pence, not {pence!r}")
        self.name = name
        self.pence = pence

    def vat(self):
        return self.pence * self.VAT_RATE // 100

    def __repr__(self):
        return f"{type(self).__name__}({self.name!r}, {self.pence!r})"

class Food(Item):
    VAT_RATE = 0

class Clothing(Item):
    pass

class ChildrensClothing(Clothing):
    VAT_RATE = 0

class HomeEnergy(Item):
    VAT_RATE = 5

class BadLine(ValueError):
    """A shopping list line that can't be read."""

KINDS = {"item": Item, "food": Food, "clothing": Clothing, "childrens": ChildrensClothing, "energy": HomeEnergy}

def parse(line):
    fields = [f.strip() for f in line.split(",")]
    if len(fields) != 3:
        raise BadLine(f"expected 3 fields: {line!r}")
    kind, name, price = fields
    if kind.lower() not in KINDS:
        raise BadLine(f"unknown kind: {kind!r}")
    if not price.isdigit():
        raise BadLine(f"bad price: {price!r}")
    return KINDS[kind.lower()](name, int(price))

def totals(items):
    return sum(i.pence for i in items), sum(i.vat() for i in items)
