## Warm-up

:::predict
import math
total = 0.0
for v in [0.1] * 10:
    total += v
print(total, total == 1.0, math.fsum([0.1] * 10) == 1.0)
:::

Adding many floats one at a time with `+=` accumulates tiny rounding errors; `math.fsum` tracks them and gives the correctly rounded total. (Since Python 3.12 the built-in `sum` also compensates for them, but a hand-written loop doesn't.) One of today's bugs lives here.

:::exercise id=c1 points=10 title="Coding 1: A grid that follows the rules"
A 9 by 9 puzzle grid is a list of 9 strings of digits and `"."` for blanks. Write `valid_grid(rows)`: whether no digit repeats in any row, any column, or any of the nine 3 by 3 boxes (blanks don't count). One pass, with sets.
@@starter
def valid_grid(rows):
    ___
@@tests
GOOD = ["53..7....", "6..195...", ".98....6.", "8...6...3", "4..8.3..1", "7...2...6", ".6....28.", "...419..5", "....8..79"]

def test_grid():
    "rows, columns, boxes"
    assert valid_grid(GOOD)
    assert not valid_grid(["83..7...."] + GOOD[1:]), "two 8s in a column"
    assert not valid_grid(["55..7...."] + GOOD[1:]), "two 5s in a row"
    box = GOOD[:]
    box[1] = "6.3195..."
    assert not valid_grid(box), "two 3s in a box"
    assert valid_grid(["." * 9] * 9)
@@solution
def valid_grid(rows):
    seen = set()
    for r, row in enumerate(rows):
        for c, ch in enumerate(row):
            if ch == ".":
                continue
            keys = (("row", r, ch), ("col", c, ch), ("box", r // 3, c // 3, ch))
            if any(k in seen for k in keys):
                return False
            seen.update(keys)
    return True
:::

Write a class `RecentCounter(window=60)` whose `hit(t)` records an event at time `t` (seconds, never decreasing) and returns how many events happened in the window `[t - window + 1, t]`. Each call must be amortised O(1).
@@starter

    ___
@@tests
import time

def test_counter():
    "a sliding window of times"
    c = RecentCounter(window=60)
    assert [c.hit(t) for t in (1, 30, 60, 61, 120, 121)] == [1, 2, 3, 3, 2, 2]

def test_fast():
    "a million hits"
    c = RecentCounter(window=1000)
    start = time.perf_counter()
    for t in range(1_000_000):
        last = c.hit(t)
    assert last == 1000 and time.perf_counter() - start < 3
@@solution
from collections import deque

class RecentCounter:
    def __init__(self, window=60):
        self.window, self.times = window, deque()

    def hit(self, t):
        self.times.append(t)
        while self.times[0] <= t - self.window:
            self.times.popleft()
        return len(self.times)

:::exercise id=d1 points=15 title="Design: finding junctions nearby"
Waymark finds junctions near a walker by splitting the map into square cells. Write `nearby_plan(junctions, area_km2, radius_km, cell_km)`: return a dict with `cells_searched` (the square of cells covering the circle: `(2 × ceil(radius / cell) + 1) ** 2`), `per_cell` (junctions per cell on average: junctions × cell area / area, 2 decimal places) and `candidates` (cells searched × per cell, rounded to a whole number), and `advice`: `"cells too big"` if `per_cell` is over 100, `"cells too small"` if `cells_searched` is over 200, else `"ok"`.
@@starter
import math

def nearby_plan(junctions, area_km2, radius_km, cell_km):
    ___
@@tests
def test_plan():
    "a grid index"
    assert nearby_plan(1_000_000, 250_000, 2, 1) == {"cells_searched": 25, "per_cell": 4.0, "candidates": 100, "advice": "ok"}
    assert nearby_plan(1_000_000, 250_000, 2, 10)["advice"] == "cells too big"
    assert nearby_plan(1_000_000, 250_000, 10, 0.5)["advice"] == "cells too small"
@@solution
import math

def nearby_plan(junctions, area_km2, radius_km, cell_km):
    cells = (2 * math.ceil(radius_km / cell_km) + 1) ** 2
    per_cell = round(junctions * cell_km * cell_km / area_km2, 2)
    advice = "cells too big" if per_cell > 100 else "cells too small" if cells > 200 else "ok"
    return {"cells_searched": cells, "per_cell": per_cell, "candidates": round(cells * per_cell), "advice": advice}

:::bughunt id=bug1 points=10 title="A total that drifted"
Adding ten 0.1 km segments one at a time with `+=` gives `0.9999999999999999`, so the check that a route is exactly 1 km fails and this prints `False`. Use `math.fsum` so it prints `True`.
@@starter

segments = [0.1] * 10

@@tests
def test_output():

@@solution
import math

segments = [0.1] * 10
total = math.fsum(segments)
print(total == 1.0)

@@tests

:::exercise id=p1 points=15 title="Deep dive: a running average you send values to"
Write a generator function `averager()`: after it's started with `next()`, each `send(value)` returns the average of all values sent so far, as a float. Then write `averages(values)`, using `averager` to return the list of running averages.
@@starter
def averager():
    ___

def averages(values):
    ___
@@tests
import inspect

def test_averager():
    "send() resumes the generator"
    gen = averager()
    assert inspect.isgenerator(gen)
    next(gen)
    assert gen.send(10) == 10.0 and gen.send(20) == 15.0 and gen.send(0) == 10.0
    assert averages([6, 7.5, 12]) == [6.0, 6.75, 8.5] and averages([]) == []
@@hint
`total, count, average = 0, 0, None`; loop for ever: `value = yield average`, then update. The first `next()` runs to the first `yield`.
@@solution
def averager():
    total, count, average = 0, 0, None
    while True:
        value = yield average
        total += value
        count += 1
        average = total / count

def averages(values):
    gen = averager()
    next(gen)
    return [gen.send(v) for v in values]
:::
